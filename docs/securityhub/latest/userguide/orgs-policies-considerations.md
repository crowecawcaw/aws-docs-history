

# Considerations and limitations for declarative policies in Security Hub CSPM

Keep the following in mind when you plan and manage AWS Security Hub CSPM declarative policies:
+ **A declarative policy applies only to accounts in AWS Organizations.** A declarative policy can manage Security Hub CSPM only in accounts that belong to your organization. It can't manage accounts that are associated only by invitation. Manage Security Hub CSPM in those accounts from their administrator account or in each account.
+ **A declarative policy governs configuration completely.** In each AWS Region where a declarative policy enables Security Hub CSPM, the declarative policy governs enablement, standards, control status, custom control parameters, and the automatic enablement of new controls. Standards that the declarative policy doesn't list are disabled, and parameters that it doesn't specify use their default values. A declarative policy can't govern only some of these settings.
+ **Governed settings are read-only in the console and API.** Governed accounts can't change these settings through the Security Hub CSPM console or API. To change them, update the declarative policy. Accounts and Regions that no declarative policy governs remain editable.
+ **An ungoverned Region is left unchanged, not disabled.** A Region that appears in neither `enable_in_regions` nor `disable_in_regions` is ungoverned. The declarative policy doesn't enable or disable Security Hub CSPM there, and existing settings don't change.
+ **Declarative policies and central configuration are mutually exclusive.** Attaching the first Security Hub CSPM declarative policy to any target disables central configuration for the entire organization. You can't turn central configuration back on until you detach every Security Hub CSPM declarative policy. For more information, see [Declarative policies and central configuration in Security Hub CSPM](orgs-policies-and-central-config.md).
+ **A declarative policy manages administrator and member associations.** When a declarative policy enables Security Hub CSPM, Security Hub CSPM designates the delegated administrator as the administrator in the Region and associates governed accounts as members, on a best-effort basis. Security Hub CSPM replaces invitation-based associations for governed accounts. Automatic associations require a Security Hub CSPM delegated administrator. An administrator account can have up to 10,000 member accounts in each Region.
+ **Disabling Security Hub CSPM removes associations, including for administrators.** A declarative policy that disables Security Hub CSPM removes the account's administrator and member associations. For the delegated administrator, it also removes the Regional administrator designation. Security Hub CSPM doesn't restore invitation-based associations that it removes.
+ **The delegated administrator needs the AWS Organizations delegation policy to manage declarative policies.** A delegated administrator can manage Security Hub CSPM members. It can't create, update, or attach Security Hub CSPM declarative policies unless the delegation policy grants it permission to manage the `SECURITYHUB_CSPM_POLICY` policy type.
+ **A declarative policy can enable Security Hub CSPM in the management account only if the service-linked role already exists there.** If the `AWSServiceRoleForSecurityHub` role doesn't exist in the management account, Security Hub CSPM isn't enabled there, even if the declarative policy enables it. Create the role first. For more information, see [Service-linked roles for AWS Security Hub CSPM](using-service-linked-roles.md).
+ **A declarative policy doesn't configure AWS Config.** Security Hub CSPM uses AWS Config rules to evaluate most controls. Enable AWS Config and record the required resources in governed accounts and Regions separately. For more information, see [Enabling and configuring AWS Config for Security Hub CSPM](securityhub-setup-prereqs.md).
+ **A declarative policy doesn't manage other Security Hub CSPM settings.** A declarative policy doesn't manage cross-Region aggregation, automation rules, custom insights, or product integrations. Configure these separately.
+ **Some standards aren't supported.** A declarative policy can't configure multicloud standards or service-managed standards, such as Service-Managed Standard: AWS Control Tower.
+ **Declarative policies don't have a home Region.** To evaluate controls for global resources in only one Region, use a Regional override.
+ **Controls without an enabled standard use a service-managed standard.** If an effective declarative policy enables a control without enabling a standard that contains it, Security Hub CSPM enables the control through [Service-Managed Standard: AWS Organizations](service-managed-standard-aws-organizations.md). While the account is governed, you can't disable this standard.
+ **Deprecated controls are ignored.** If a declarative policy references a deprecated control, Security Hub CSPM skips that control.
+ **Declarative policy changes apply asynchronously.** A declarative policy change propagates across your organization, and Security Hub CSPM reconciles it over time. Security Hub CSPM also periodically corrects drift, such as a newly released control that hasn't yet been configured. Allow time for a change to apply before you conclude that it didn't take effect.
+ **Detaching a declarative policy doesn't disable Security Hub CSPM.** When you detach a declarative policy from an entity, declarative policies inherited from parent entities can still apply. If no effective declarative policy remains, Security Hub CSPM, its standards, and its controls stay in their current state, and the account becomes self-managed. Future organization changes no longer configure Security Hub CSPM automatically unless an inherited declarative policy still covers them.
+ **Disabling the policy type turns off all Security Hub CSPM declarative policies.** Disabling Security Hub CSPM in a declarative policy, detaching one, and disabling the `SECURITYHUB_CSPM_POLICY` policy type are three different actions. When you disable the policy type on the organization root, Security Hub CSPM declarative policies no longer govern any account. In previously governed accounts, Security Hub CSPM stays in its current state.
+ **Availability.** Security Hub CSPM declarative policies are available in the AWS commercial, AWS GovCloud (US), and China Regions.



# Insights in online evaluation

Insights identifies recurring failure patterns in agent traffic. Add the `Builtin.FailureAnalysis` Insight Evaluator to an online evaluation configuration to analyze each sampled session and update related Agent Insights over time.

Online evaluation insights update as the evaluation processes sampled live traffic. Batch Insight Evaluators generate point-in-time insights for a selected dataset. When the default Agent Insight Store is enabled and active, the Agent Insights APIs surface findings from both sources. For the processing model and a comparison, see [How Insights works](insights-how-it-works.md).

## Enable Insights
<a name="online-evaluations-insights-create"></a>

When you call `CreateOnlineEvaluationConfig`, include `Builtin.FailureAnalysis` in `evaluators`, identify the agent with `serviceNames`, provide an evaluation execution role, and enable the configuration. For the complete online evaluation request, see [Create online evaluation](create-online-evaluations.md). For an end-to-end CLI and SDK walkthrough, see [Get started with Insights](insights-getting-started.md).

To create the configuration with the AgentCore CLI, run `agentcore eval online-eval create` with `--evaluators Builtin.FailureAnalysis`. When the evaluators include `Builtin.FailureAnalysis`, the command prints the command that lists the resulting Agent Insights:

```bash
note: Insights generated by Builtin.FailureAnalysis are not in this output.
      Run: agentcore eval insight list --application-name MyAgent.DEFAULT
```

If you add the configuration to an AgentCore CLI project with `agentcore add online-eval`, run `agentcore deploy`. Agent Insights become available after deployment when the default Agent Insight Store is enabled and active.

## Read Insights
<a name="online-evaluations-insights-read"></a>

Use the same OpenTelemetry service name as `applicationName` when you call `ListAgentInsights`. Then call `GetAgentInsight` to read the root causes, suggested fixes, affected-session count, and sample sessions for one pattern. Use the sample session and span identifiers to inspect the source traces.

For AWS CLI, AgentCore CLI, and SDK examples, see [List, read, archive, and restore Agent Insights](insights-manage.md).

## Requirements and considerations
<a name="online-evaluations-insights-requirements"></a>
+ Your online evaluation must use `Builtin.FailureAnalysis`. Other numerical or categorical evaluators don’t generate Agent Insights.
+ The default Agent Insight Store starts disabled. Enable it and wait until it is active before the Insight Evaluator can add Agent Insights. Disabling the Store doesn’t stop the online evaluation or its session-level results.
+ The evaluation needs enough related failure evidence to form a pattern. An enabled configuration might not immediately produce an Agent Insight.
+ Use a consistent `serviceName` for traffic from the same agent. Changing the service name changes the agent-level aggregation scope.
+ Depending on the source Region, built-in evaluator requests can be processed in another Region. See [Cross region inference](evaluations-cross-region-inference.md).

For Store configuration and encryption, see [Manage the Agent Insight Store](insights-store.md) and [Encryption at rest for Agent Insights](insights-security.md).

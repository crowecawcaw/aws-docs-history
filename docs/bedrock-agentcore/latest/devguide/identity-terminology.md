# AgentCore Identity terminology

AgentCore Identity uses specific terminology to describe the components, processes, and
relationships involved in workload identity management and credential handling.
Understanding these terms will help you better comprehend how the service
orchestrates secure authentication and authorization across multiple parties in
agent workflows.

| AgentCore Identity terminology definitions | Term                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Definition |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| **Identity and<br>Authentication**         |
| Agent                                      | An AI-powered application or automated workload that performs<br>tasks on behalf of users by accessing AWS resources and<br>third-party services. Agents act with pre-authorized user consent,<br>to accomplish user goals, such as retrieving data from APIs,<br>processing information, or integrating with third-party systems.<br>Unlike traditional applications that run with static credentials,<br>agents require dynamic identity management to securely access<br>resources across multiple trust domains while maintaining proper<br>authentication and authorization boundaries.                                                                                  |
| Agent identity                             | A unique identifier and associated metadata for an AI agent or<br>automated workload. Agent identities are implemented as workload<br>identities with specific attributes that identify them as agents,<br>enabling specialized agent capabilities while maintaining<br>compatibility with broader workload identity standards. Agent<br>identities enable agents to authenticate as themselves rather than<br>impersonating users, supporting delegation-based access<br>patterns.                                                                                                                                                                                           |
| Agent identity directory                   | A centralized registry that manages agent identities and their<br>associated metadata and access policies. Similar to Cognito User<br>Pools, it acts as a unit of governance for organizing agent<br>identities within an account or region.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Workload identity                          | The underlying technical implementation for agent identities,<br>representing a logical application or workload that is independent<br>of specific hardware or infrastructure. Workload identities can<br>operate across different environments while maintaining consistent<br>authentication. Agent identities are a specialized type of workload<br>identity with additional agent-specific attributes and<br>capabilities.                                                                                                                                                                                                                                                |
| **Integration<br>and Protocols**           |
| Cross-service agents                       | AI agents that perform actions across multiple services, which<br>may include accessing system resources (using machine-to-machine<br>authentication) or user-specific data (using user-delegated access).<br>Examples include agents that integrate with multiple backend systems<br>for data processing or agents that access a user's calendar, email,<br>and document storage. These agents require sophisticated identity<br>management to operate securely across different trust<br>domains.                                                                                                                                                                           |
| MCP client                                 | A client component that allows agents to communicate with MCP<br>servers to access external tools and resources. MCP clients present<br>authentication tokens to access MCP tools securely.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| MCP server                                 | An intermediate server that hosts tools and resources for MCP<br>clients. MCP servers act as OAuth 2.0 resource servers when accessed<br>by agents and as OAuth 2.0 clients when accessing downstream<br>resources.                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Model context protocol (MCP)               | MCP is an open protocol that standardizes how applications<br>provide context to language models. AgentCore Identity is MCP-compliant,<br>supporting standard protocols for agent-to-tool communication and<br>enabling secure integration with MCP servers and tools.                                                                                                                                                                                                                                                                                                                                                                                                        |
| **OAuth and<br>Token Management**          |
| OAuth 2.0                                  | An industry-standard authorization framework (defined in [RFC<br>6749](https://datatracker.ietf.org/doc/html/rfc6749 "https://datatracker.ietf.org/doc/html/rfc6749")) that enables applications to obtain limited access<br>to user accounts on external services without exposing user<br>credentials. OAuth 2.0 provides secure delegation by allowing users<br>to grant third-party applications access to their resources through<br>access tokens rather than sharing passwords. For agent applications,<br>OAuth 2.0 enables secure access to user data across multiple<br>services while maintaining proper authentication boundaries and user<br>consent mechanisms. |
| OAuth 2.0 authorizer                       | An SDK component that authenticates and authorizes incoming OAuth<br>2.0 API requests to agent endpoints. It validates tokens before<br>allowing access to agent services.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| OAuth 2.0 client credentials grant (2LO)   | OAuth client credentials grant used for machine-to-machine<br>authentication where no user interaction is required. Agents use 2LO<br>to authenticate themselves directly with resource servers.                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| OAuth 2.0 authorization code grant (3LO)   | OAuth authorization code grant that involves user consent and<br>interaction. Agents use 3LO when they need explicit user permission<br>to access user-specific data from external services like Google<br>Calendar or Salesforce.                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Agent access token                         | An AWS-signed token that contains both workload identity and<br>user identity information, enabling downstream services to make<br>authorization decisions based on both identities. These tokens are<br>created through the token exchange process.                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Security and<br>Trust**                  |
| Identity propagation                       | The process of maintaining and passing identity context through a<br>chain of service calls. This enables downstream services to make<br>authorization decisions based on both the calling service identity<br>and the original user identity.                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Trust domain                               | A security boundary within which entities share common<br>authentication and authorization mechanisms. Agent workflows often<br>span multiple trust domains, requiring careful identity propagation<br>and token exchange.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Request verification security              | A security model where every request is authenticated and<br>authorized regardless of source or previous trust relationships.<br>AgentCore Identity implements request verification to ensure validation of<br>all access requests.                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Service<br>Components**                  |
| Resource credential provider               | A component that manages connections to external identity<br>providers and resource servers, handling OAuth 2.0 authorization<br>flows and credential retrieval. It orchestrates the complex process<br>of obtaining and refreshing credentials from third-party services.<br>For detailed configuration information, see [Configure credential provider](resource-providers.md "resource-providers.md").                                                                                                                                                                                                                                                                     |
| Token vault                                | A secure storage system for OAuth 2.0 tokens, API keys, and other<br>credentials that operates with strict access controls. The token<br>vault ensures credentials can only be accessed by the specific agent<br>and user combination that originally obtained them.                                                                                                                                                                                                                                                                                                                                                                                                          |

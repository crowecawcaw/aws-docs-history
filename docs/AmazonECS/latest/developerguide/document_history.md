| AWS Fargate platform version 1.4.0                                                                                                                                                                                                                                                                                                              | AWS Fargate platform version 1.4.0 is released, which contains the<br>following features:<br>• Added support for using Amazon EFS file system volumes for<br>persistent task storage. For more information, see [Use Amazon EFS volumes with Amazon ECS](efs-volumes.md "efs-volumes.md").<br>• The ephemeral task storage has been increased to 20 GB.<br>For more information, see [Fargate task ephemeral storage for Amazon ECS](fargate-task-storage.md "fargate-task-storage.md").<br>• The network traffic behavior to and from tasks has been<br>updated. Starting with platform version 1.4, all Fargate tasks<br>receive a single elastic network interface (referred to as the<br>task ENI) and all network traffic flows through that ENI within<br>your VPC and will be visible to you through your VPC flow logs.<br>For more information, see [Amazon ECS task networking options for the Fargate launch<br>type](fargate-task-networking.md "fargate-task-networking.md").<br>• Task ENIs add support for jumbo frames. Network interfaces are<br>configured with a maximum transmission unit (MTU), which is the<br>size of the largest payload that fits within a single frame. The<br>larger the MTU, the more application payload can fit within a<br>single frame, which reduces per-frame overhead and increases<br>efficiency. Supporting jumbo frames will reduce overhead when<br>the network path between your task and the destination supports<br>jumbo frames, such as all traffic that remains within your<br>VPC.<br>• CloudWatch Container Insights will include network performance metrics for<br>Fargate tasks. For more information, see [Monitor Amazon ECS containers using Container Insights with enhanced observability](cloudwatch-container-insights.md "cloudwatch-container-insights.md").<br>• Added support for the task metadata endpoint v4 which provides<br>additional information for your Fargate tasks, including<br>network stats for the task and which Availability Zone the task<br>is running in. For more information, see [Amazon ECS task metadata endpoint version 4](task-metadata-endpoint-v4.md "task-metadata-endpoint-v4.md").<br>• Added support for the `SYS_PTRACE` Linux parameter<br>in container definitions. For more information, see [Linux parameters](task_definition_parameters.md#container_definition_linuxparameters "task_definition_parameters.md#container_definition_linuxparameters").<br>• The Fargate container agent replaces the use of the Amazon ECS<br>container agent for all Fargate tasks. This change should not<br>have an effect on how your tasks run.<br>• The container runtime is now using Containerd instead of<br>Docker. This change should not have an effect on how your tasks<br>run. You will notice that some error messages that originate<br>with the container runtime will change from mentioning Docker to<br>more general errors.<br>For more information, see [Fargate platform versions for Amazon ECS](platform-fargate.md "platform-fargate.md"). | April 8, 2020      |

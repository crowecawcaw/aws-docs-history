# Stack from CloudFormation Template | Remediate Drift

Remediate the drift (out-of-band changes) in a stack, bringing the stack in sync and enabling you to perform future updates using the available Update CTs. Note: up to 10 drifted resources will be remediated per RFC.

**Full classification:** Management | Custom Stack | Stack from CloudFormation Template | Remediate drift

Until you submit it, the RFC remains in the editing state and does not start. ###### Important Stack remediation modifies the stack template and/or parameter values. Once remediation is complete, you must update your local template repositories, or any automation, that would be updating the remediated stack, with the latest template and parameters provided in the RFC summary of the remeditation. It is very important to do this, because using the old template and/or parameters can cause destructive changes on the stack resources. For more details, including a list of _Limitations_, see [Drift remediation FAQs](../userguide/ex-rfc-updates-and-dd.md#drift-remeditate-faqs "../userguide/ex-rfc-updates-and-dd.md#drift-remeditate-faqs"). ###### Note When using manual CTs, AMS recommends that you use the ASAP **Scheduling** option (choose **ASAP** in the console, leave start and end time blank in the API/CLI) as these CTs require an AMS operator to examine the RFC, and possibly communicate with you before it can be approved and run. If you schedule these RFCs, be sure to allow at least 24 hours.

# Migrating from TIBCO EMS server to Amazon MQ

You can migrate from TIBCO EMS to Amazon MQ.

## Terminologies

The following is a list of common TIBCO EMS concepts and how they relate to Amazon MQ.

| **TIBCO EMS**         | **Amazon MQ**                                                                                                                                                                                                                                                                        |                                           |                                                                                                                                                                                                                                             |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Component**         | **Description**                                                                                                                                                                                                                                                                      | **Component**                             | **Description**                                                                                                                                                                                                                             |
| EMS Server            | TIBCO EMS Server is a message broker that supports<br>standards-based Java Message Service (JMS) 1.1 and 2.0.<br>It also supports TIBCO proprietary messaging formats,<br>**FTL**, **Rendezvous**, and **SmartSockets**.                                                             | Broker                                    | Broker in Amazon MQ is equivalent to TIBCO EMS Server.<br>It provides support for industry-standard APIs such as<br>JMS and NMS, and protocols such as **AMQP**, **STOMP**, **MQTT**,<br>and **WebSocket**.                                 |
| Static Destination    | Configuration information for a static destination is<br>stored in configuration files for the EMS server.                                                                                                                                                                           | Startup Destination                       | Amazon MQ allows you to create destinations when the broker<br>is started by configuring Startup Destinations.                                                                                                                              |
| Dynamic Destination   | Dynamic Destination is created as required by the client<br>application and exists as long as there are messages or<br>consumers associated with a destination.                                                                                                                      | Destination                               | In Amazon MQ, a destination is, by default,<br>created automatically when it is used. You can use the _Delete Inactive Destinations_<br>feature in order to replicate the behavior of Dynamic Destinations in TIBCO EMS.                    |
| Temporary Destination | A Temporary Destination is used for reply messages in<br>request/reply interactions.                                                                                                                                                                                                 | Temporary Destination                     | A Temporary Destination is used for reply messages in<br>request/reply interactions.                                                                                                                                                        |
| Queue                 | A queue is a mode to provide point to point messaging<br>channel from producers to consumers                                                                                                                                                                                         | Queue                                     | Similar to that of TIBCO EMS, Amazon MQ’s Queue is a<br>mode to provide point-to-point messaging channels from<br>producers to consumers                                                                                                    |
| Route                 | TIBCO EMS servers have to enable and configure routing<br>to route messages to one or more servers. A route forwards<br>messages between corresponding global destinations.                                                                                                          | Network Connector                         | [Networks of Brokers](../developer-guide/network-of-brokers.md "../developer-guide/network-of-brokers.md")<br>can connectto each other on a Network<br>Connector and allows connections across Availability Zones and region.               |
| Routed Queue          | A Routed Queue has to be configured on another EMS<br>server for messages to be forwarded to or from a Queue.<br>Queue messages can travel only one hop to the home<br>queue, and one hop from the home queue.                                                                       | Network of Brokers                        | This is achieved using a network of brokers. Amazon MQ<br>provides a richer feature-set to work with destination<br>behavior in [Networks of Brokers](../developer-guide/network-of-brokers.md "../developer-guide/network-of-brokers.md"). |
| Topic                 | Topics implement \*publish and subscribe<br>• messaging,<br>and are equivalent to topics in Amazon MQ.                                                                                                                                                                               | Topics                                    | Topics in Amazon MQ are equivalent to topics in TIBCO EMS.                                                                                                                                                                                  |
| Global Topic          | A Global Topic has to be configured on another EMS<br>server for messages to be forwarded to or from a Topic.<br>In a multi-hop zone, Topic messages are forwarded to all<br>servers connected by routers within the zone. In a<br>one-hop zone, topic messages travel only one hop. | Network of Brokers                        | This is achieved using a network of brokers. Amazon MQ<br>provides a richer feature-set to work with destination<br>behavior in [Networks of Brokers](../developer-guide/network-of-brokers.md "../developer-guide/network-of-brokers.md"). |
| Destination Bridges   | This allows all messages delivered to one destination to<br>also be delivered to the bridged destination. It is most<br>commonly used to create durability of messages published<br>on a topic using the topic to queue bridge.                                                      | Virtual Topics and Composite Destinations | Topic to queue bridge-like functionality can be achieved<br>using Virtual Topics in Amazon MQ. Other bridges can be<br>migrated using Composite Destinations in Amazon MQ.                                                                  |
| Message Store         | EMS server writes persistent messages to disk and<br>provides file-based and database stores. For file-based<br>stores, you have to truncate the files periodically to<br>relinquish disk space.                                                                                     | N/A                                       | Amazon MQ also supports message persistence. Amazon MQ<br>is a managed service and the overall storage is fully<br>managed by AWS.                                                                                                          |

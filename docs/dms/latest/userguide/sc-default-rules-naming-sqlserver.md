

# Naming rules
<a name="sc-default-rules-naming-sqlserver"></a>

The following naming rules apply when your source database is Microsoft SQL Server. DMS Schema Conversion applies your transformation rules first, and then applies the default rules for case, prefixes, uniqueness, and length to the result.

## Naming by object type
<a name="sc-default-rules-naming-sqlserver-objecttypes"></a>

The following table lists the rule that DMS Schema Conversion applies to each kind of database object. Where DMS Schema Conversion generates a name rather than deriving it from the source, the table shows the pattern.


| Object type | Naming rule | Example | 
| --- | --- | --- | 
| Database | Not created. Its name is merged into the schema name with the default parameter (DB\_SCHEMA) in the setting Schema name template; with parameter (DB) it becomes the schema name; with parameter (SCHEMA) it is dropped. Code that references another database (OtherDB.dbo.Table) is rewritten to the merged schema name and resolves only if that database is converted into the same target database; otherwise an action item is raised. | MyDatabase.dbo → mydatabase\_dbo / mydatabase / dbo; OtherDB.dbo.Table → otherdb\_dbo.table | 
| Schema | Database and schema combined per the Schema name template setting, then lowercased. | MyDatabase.dbo → mydatabase\_dbo | 
| Table | Schema-qualified, lowercased. | MyDatabase.dbo.UserAccounts → mydatabase\_dbo.useraccounts | 
| Temporary table | Leading \# becomes t$. No schema qualifier is added. | \#TempResults → t$tempresults | 
| Table variable | The @ is dropped and the declaring routine's name is appended. | @Rows declared in usp\_load → rows$usp\_load | 
| Table-valued function return table | The table declared in RETURNS @name TABLE (…) is named after the function with a fixed suffix; its own name isn't used. | RETURNS @Result TABLE in fn\_Split → fn\_split$tmptbl | 
| View | Schema-qualified, lowercased. | MyDatabase.dbo.V\_Orders → mydatabase\_dbo.v\_orders | 
| Index | Prefixed IX\_ and qualified with the table name when Generate unique names for indexes is on (the default), so the name is unique within the schema. The assembled name is re-truncated if needed. | Idx2 on TestNonClusteredIndex → ix\_testnonclusteredindex\_idx2 | 
| Column | Lowercased if a plain identifier. | Order\_ID → order\_id | 
| Parameter | Leading @ replaced by par\_. | @CustomerId → par\_customerid | 
| Variable | Leading @ replaced by var\_. | @Total → var\_total | 
| Procedure, function | Schema-qualified, lowercased. Scalar, table-valued, and inline functions all become functions. | dbo.usp\_Load → mydatabase\_dbo.usp\_load | 
| Sequence | Schema-qualified, lowercased. | dbo.Seq\_Order → mydatabase\_dbo.seq\_order | 
| User-defined table type | Schema-qualified with a table-type suffix. A plain user-defined type becomes a domain and takes no suffix. | Employee2Client → employee2client$aws$t | 
| Trigger (defined in the source) | Keeps its name, lowercased. Triggers that use both inserted and deleted might be split into several triggers. | trg\_Products\_OnUpdate → trg\_products\_onupdate | 
| Trigger function (for a source trigger) | The converted trigger name prefixed with fn\_. | trg\_Products\_OnUpdate → fn\_trg\_products\_onupdate | 
| Procedure companion for open result sets (when Create additional procedures for open datasets is on) | A second procedure is generated with a fixed suffix. | usp\_report → usp\_report$TMP | 
| Trigger and function generated by the conversion | Built from the table name with an event suffix: \_biu for ROWVERSION and computed columns, \_bi / \_bu for sparse column sets, tr\_hist\_ for temporal tables. See the section about conversions that create additional target objects. | table Orders → tr\_orders\_biu, fn\_tr\_orders\_biu | 

## Settings that affect naming
<a name="sc-default-rules-naming-sqlserver-settings"></a>

Several conversion settings change how DMS Schema Conversion generates names: *Schema name template*, *Keep object names in the same case*, *Generate unique names for indexes*, *Keep original parameter names*, *Convert procedures to functions*, *Create stubs in separate schema*, *Convert unsupported built-ins to stubs*, and *Create additional procedures for open datasets*. For their values and defaults, see [SQL Server to PostgreSQL conversion settings](schema-conversion-sql-server-postgresql.md). The following naming rules assume the default values.

## Transformation rules that affect naming
<a name="sc-default-rules-naming-sqlserver-transformation"></a>

Transformation rules let you override the name of selected objects. You can rename them; add, remove, or replace a prefix or suffix; or force lowercase. DMS Schema Conversion applies transformation rules before the default naming rules, so casing, uniqueness, and truncation still run afterward on the name that you specify. For the rule syntax, actions, and object locators, see [Transformation rules in DMS Schema Conversion](sc-transformation-rules.md). The following naming rules assume that no transformation rules are defined.

## Case sensitivity
<a name="sc-default-rules-naming-sqlserver-case"></a>

The following describes how DMS Schema Conversion handles the case of source object names. PostgreSQL folds unquoted identifiers to lowercase, so the case that a name arrives in determines whether you can use it unquoted in the target.

**Note**  
**Plain identifiers.** Most naming rules apply only to a *plain identifier* — a name matching `^[A-Za-z_][0-9A-Za-z$_]*$` that isn't a target reserved word. Any name containing spaces, dots, quotes, or non-ASCII characters is left exactly as it is, and is quoted in the target instead. This is the single most useful rule to remember: **if a name isn't a plain identifier, its case is never changed.**

**Note**  
**Case sensitivity is controlled by one setting.** By default, every plain identifier is lowercased. Enabling *Keep object names in the same case* preserves the original case instead. Two related properties — whether the source database and the source server are themselves case sensitive — are read from your source database rather than configured, and DMS Schema Conversion doesn't require them for case preservation. Routine parameters are additionally preserved only where another parameter of the same name would otherwise collide.

<a name="sc-default-rules-naming-sqlserver-case-examples"></a>


| SQL Server input | Output (default) | Why | 
| --- | --- | --- | 
| sourceTableName | sourcetablename | Plain identifier → lowercased | 
| AccessToken | accesstoken | Plain identifier → lowercased | 
| \_Conventions\_Test\_3 | \_conventions\_test\_3 | Plain identifier → lowercased | 
| \_Conventions test 2 | "\_Conventions test 2" | Contains space → not plain, never lowercased | 
|  space\_02 | " space\_02" | Starts with space → not plain | 
| Б'Ёка1 | "Б'Ёка1" | Non-ASCII → not plain, never lowercased | 
| a'b'c | "a'b'c" | Contains quotes → not plain | 

## Name length and truncation
<a name="sc-default-rules-naming-length-sqlserver"></a>

PostgreSQL limits identifiers to 63 bytes, whereas SQL Server allows 128 characters. Names most often exceed the PostgreSQL limit because of the names that DMS Schema Conversion assembles itself — merged database and schema names, and index names qualified with their table. The limit is a property of the target engine and isn't configurable.

A name can exceed the limit only after DMS Schema Conversion rebuilds it. The SQL Server index `IX_VTN_Course_CompanyID_CourseType_IsDeleted_CourseID` on table `VTN_Course` is 53 characters, within the PostgreSQL limit, but the setting *Generate unique names for indexes* rebuilds the name as `ix_<table>_<index>`. The assembled name is longer than 63 bytes, so DMS Schema Conversion shortens it and adds a `$` plus a short hash, giving `ix_vtn_course_ix_vtn_course_companyid_coursetype_isdel$3d2b343f`.

DMS Schema Conversion derives the hash from the object's full owner path — and, for routines, from the parameter signature as well — so two long names that share a prefix still convert to different target names instead of colliding.

## Reserved words treated as non-plain identifiers
<a name="sc-default-rules-naming-reserved-sqlserver"></a>

DMS Schema Conversion doesn't treat a source name that matches one of the following PostgreSQL reserved words as a plain identifier. It keeps the name exactly as spelled in your source and quotes it in the target. Because the name is quoted, you must quote it everywhere that you reference it in the target.

For a SQL Server source, a table named `Order` becomes `"Order"`.

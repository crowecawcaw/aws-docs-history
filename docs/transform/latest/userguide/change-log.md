Additionally, AWS Transform MGN is in scope for FedRAMP Class D, and can be used independently to migrate resources that require FedRAMP Class D compliance. | [What's New post](https://aws.amazon.com/about-aws/whats-new/2026/08/aws-transform-fedramp-class-c/), [Compliance in Scope](https://aws.amazon.com/compliance/services-in-scope/FedRAMP/) | 
| 2026-08-24 | AWS Transform for migrations adds security posture migration to existing VPCs | AWS Transform for migrations now offers a second network migration option: apply your source security posture to VPCs you have already provisioned. You can deploy the security groups directly with AWS Transform or generate Infrastructure as Code (CloudFormation, AWS CDK, Terraform, or Landing Zone Accelerator). | [Documentation](https://docs.aws.amazon.com/transform/latest/userguide/transform-vmware-apply-security-posture.html) |

Subnets and server IP addresses remain unchanged by the split. This recommendation uses application and environment data from your migration plan and is available only after migration planning. | [Documentation](https://docs.aws.amazon.com/transform/latest/userguide/transform-vmware-migrate-network-new-vpcs.html#transform-vmware-guided-recommendations) |

Removal is limited to unused ingress rules, where the absence of observed traffic is a reliable signal that a rule is unused. | [Documentation](https://docs.aws.amazon.com/transform/latest/userguide/transform-vmware-migrate-network-new-vpcs.html#transform-vmware-guided-recommendations) |

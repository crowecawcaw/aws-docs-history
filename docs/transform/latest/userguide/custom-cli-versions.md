version.

| 3.12.0 (latest)         | August 26, 2026   | • The CLI now supports `atx ct` commands on<br>Windows.<br>• Changed `atx ct` remote Amazon EC2 analyses to<br>default to 5 parallel workers.<br>• Added a `-q`, `--quiet` flag to<br>`atx exec` and `atx custom def exec`. The flag<br>mutes tool-call output for auto-approved tools, while tools that<br>require approval still render in full. Combine it with<br>`--trust-all-tools` to silence all tool<br>activity.<br>• Fixed `file://` configuration paths on<br>Windows, including paths with spaces, so they now resolve<br>correctly.<br>• Fixed reading of files that have a UTF-8 byte-order mark,<br>so first-line edits and searches no longer fail.<br>• Fixed file overwrites to preserve the original line<br>endings, avoiding spurious whole-file changes on<br>Windows.<br>• Fixed analysis report parsing and patch application on<br>Windows to handle CRLF line endings.<br>• Fixed status symbols to fall back to plain text on older<br>Windows terminals that cannot display them.<br>• Fixed an issue where a kill-family command issued by the<br>agent through shell expansion could terminate the CLI's own process.<br>For example, commands such as `kill $PPID` or<br>`kill $$` could affect the CLI. The `shell`<br>tool now checks these against the CLI's own process and its ancestor<br>chain before running them.<br>• Fixed clone operations to retry on transient network<br>failures.<br>• Fixed custom analyses to retry repository resolution when<br>it first returns no repositories.<br>• Fixed comprehensive and custom analyses to keep the local<br>clone needed for artifact upload.<br>• The CLI now rejects invalid `--severity`<br>filters on remote analyses with a clear error. Previously, it ignored<br>them.<br>• Fixed an issue where a completed recurring scheduled<br>analysis reported 0 findings even when findings existed.<br>`atx ct analysis get` and<br>`atx ct analysis run --wait` now report the correct<br>finding count.<br>• Fixed an issue where AWS Batch remote analyses could<br>fail with `InsufficientFreeAddressesInSubnet` when a subnet was<br>low on IP addresses. The dispatcher now waits for available IP<br>capacity before submitting each job.<br>• Fixed a dispatcher stall where AWS Batch and Amazon EC2<br>jobs could get stuck pending under high deferral volume. This could<br>happen with IP-constrained subnets or busy Amazon EC2 workers.<br>• Fixed remote provisioning to advertise the correct<br>region-qualified dispatcher IAM role name. This ensures the PassRole<br>grant an administrator sets up matches the role the dispatcher<br>uses.<br>• To apply the dispatcher fixes to an already-deployed<br>stack, run the following command:<br>`atx ct remote update --mode ec2 | batch --stack-name<br><stack-name> [--execute] [--ack]` |
| 3.11.0                  | August 19, 2026   | • Added `--repos` to<br>`atx ct remediation create` for multi-repo remediation in<br>a single command.<br>• Added `--transformation-name` to<br>`atx ct remote remediation` to run a remediation directly<br>from a transformation definition without requiring existing<br>findings.<br>• Added `--json` output to<br>`atx ct analysis run` for machine-readable<br>results.<br>• Added an Agent Minutes cost summary to<br>`atx ct analysis get` and<br>`atx ct remediation status`.<br>• Added a local file export for<br>`atx ct remote provision` in dry-run mode: the generated<br>AWS CloudFormation templates are now written to a local file<br>(override the location with `--out-dir`) for review<br>before deployment.<br>• Fixed an issue where kill-family commands issued by the<br>agent could terminate the CLI's own process. Affected commands<br>include `pkill -f node`, `xargs kill`, and<br>`find -exec kill`. The `shell` tool now checks<br>these against the CLI's own process and its ancestor chain before<br>running them.<br>• Fixed an issue where GitLab source discovery used<br>repository topics as the language field. This could cause<br>repositories with special characters in their topics to fail<br>registration. Language is no longer inferred from<br>topics.<br>• Fixed an issue where `atx ct` commands that<br>failed could exit silently with empty output. The CLI now surfaces<br>actionable error messages.<br>• Fixed an issue where finalizing a local analysis run<br>could error when the service reported the run was already<br>terminal.<br>• Fixed an issue where<br>`atx ct remote update` did not update the shared<br>dispatcher infrastructure. As a result, upgrading the CLI and running<br>`remote update` continued to use the previously deployed<br>dispatcher. `remote update` now reconciles the<br>dispatcher.<br>• Fixed an issue where remote analysis runs (Amazon EC2 or<br>AWS Batch) could report a false failure. This occurred when all<br>repositories in a scoped run had already completed on the<br>service.<br>• Fixed an issue where `atx ct` repository<br>discovery could silently drop repositories the service rejected. The<br>CLI now counts and reports skipped repositories ("N repositories<br>were skipped"), with an overflow summary for large<br>organizations.<br>• Changed user-facing error and warning messages to refer<br>to AWS Transform and state a clear next step (refresh credentials,<br>retry, or contact support). Messages no longer reference internal<br>service names.                                                                                                                                                                                                   |
| 3.10.0                  | August 10, 2026   | • Added support for<br>`background=true` in the `shell` tool for<br>long-running or non-terminating commands (dev servers, build<br>watchers, `tail -f`). It returns immediately with a<br>process ID instead of waiting for the command to exit. Up to 5<br>background processes can be tracked at once.<br>• Added new `check_background_shell` and<br>`stop_background_shell` tools to monitor and terminate<br>background processes.<br>• Added `llmConfig` to the CLI configuration<br>allowlist, enabling users to customize LLM settings via config<br>files.<br>• Added `--mode aws-managed` to<br>`atx ct schedule create` and<br>`atx ct remote analysis` to run analyses using fully<br>managed AWS infrastructure without provisioning your own<br>Amazon EC2 or AWS Batch resources.<br>• Added `--schedule-id` and<br>`--display-name` options to<br>`atx ct analysis` to filter results by schedule and<br>identify analyses by a human-readable label.<br>• Added `--region` support for<br>`--mode aws-managed` operations, allowing you to target<br>a specific AWS Region for managed analysis runs.<br>• Improved reliability of<br>`atx ct schedule get`, `enable`,<br>`disable`, and `delete`<br>commands.<br>• Improved accuracy and consistency of<br>`atx ct schedule list` results.<br>• Added `--stack-name` to<br>`atx ct schedule create` to pin a schedule to a<br>specific target stack.<br>• Added new `atx ct analysis list-artifacts`<br>and `atx ct analysis get-artifact` commands for<br>retrieving output artifacts from AWS-managed infrastructure<br>analysis runs.<br>• Fixed an issue where background processes tracked by<br>the CLI were not properly terminated on CLI exit, which could leave<br>orphaned processes running.<br>• Fixed an issue where<br>`atx ct schedule create` did not reject the<br>`--workers` and `--batch-name` flags when<br>used with `--mode aws-managed`.<br>• Fixed inconsistent wording in schedule not-found error<br>messages.<br>• Fixed an issue where endpoint overrides were not<br>resolved consistently across all CLI commands.<br>• Improved accuracy of duplicate schedule name<br>detection.<br>• Fixed an issue where<br>`atx ct remote analysis --resume` did not resume a<br>partially-completed batch run. The flag is now<br>`--resume-incomplete`, which re-runs only the<br>repositories that did not finish (failed, interrupted, or not yet<br>started) and skips completed ones.<br>• Updated `atx ct schedule --help` to<br>include AWS Managed Analysis run<br>offerings.                                                                                                                                                                                                                   |
| 3.9.0                   | July 31, 2026     | • Improved the performance of<br>`atx custom def export-ki-markdown` on transformation<br>definitions that contain many knowledge items. The command no<br>longer makes a redundant service call for each knowledge item, so<br>it runs significantly faster and no longer times out on large<br>definitions. Also fixed cases where an export could omit knowledge<br>items or report an inconsistent total.<br>• Fixed an issue where agentic-readiness and<br>modernization-readiness analyses run with<br>`atx ct analysis run` could report zero findings for<br>certain report formats. Findings are now recovered<br>reliably.<br>• Fixed an issue where scheduled analyses created with<br>`atx ct schedule create` against GitLab, Bitbucket, or<br>local sources could fail on every run while trying to retrieve<br>credentials. The source provider is now determined automatically<br>from your registered source, and the `--provider` option<br>is no longer required.<br>• Fixed an issue where security analyses run in remote<br>(AWS Batch or EC2) environments could incorrectly report that the<br>Security Agent was not configured. The CLI now detects a configured<br>Security Agent correctly and reports transient credential or<br>throttling errors more gracefully.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 3.8.0                   | July 29, 2026     | • Added the `--recurrence` option to<br>`atx ct schedule create`, so you can set a schedule's<br>cadence in plain terms (`daily`,<br>`weekly:<MONDAY..SUNDAY>`, or<br>`monthly:<1..28>`) instead of writing a raw cron<br>expression.<br>• Added the `--existing-scheduler-role-arn`<br>option to `atx ct remote provision`, so you can reuse<br>an IAM role that your administrator has already created for the<br>scheduler instead of having the CLI create one during<br>provisioning.<br>• Added the<br>`--existing-instance-profile-name` option to<br>`atx ct remote provision --mode ec2`, so you can attach<br>an IAM instance profile that your administrator has already created<br>instead of having the CLI create the transform role and instance<br>profile.<br>• Improved transformation selection guidance so that it<br>now uses detection metadata, such as severity and matching<br>criteria, when available. Canceling now<br>reliably marks the analysis as canceled.<br>• Fixed an issue where `atx ct schedule delete`<br>could leave a lingering analysis record behind. Deleting a schedule<br>now also removes the underlying scheduled<br>analysis.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

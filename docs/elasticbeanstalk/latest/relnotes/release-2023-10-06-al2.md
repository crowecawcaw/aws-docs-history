# Release: Elastic Beanstalk Amazon Linux 2 platform updates on October 06, 2023

This release provides new versions for AWS Elastic Beanstalk platforms based on Amazon Linux 2. The release includes security updates.
It also includes
AMI,

Docker,
ECS based Docker,
Go,
Corretto,
Tomcat,
.NET Core,
Node.js,
PHP,
Python,
and Ruby updates.

**Release date:** October 06, 2023

## Changes

The following table lists the changes included in this release.

###### Notes

- These release notes focus on changes to currently supported platform branches. For full version information of Elastic Beanstalk retiring (deprecated)
  platform branches, see [Elastic Beanstalk platform versions scheduled for retirement](../platforms/platforms-retiring.md "../platforms/platforms-retiring.md") in the
  _AWS Elastic Beanstalk Platforms_ guide.
- Be aware that at the time these release notes are published, the new platform versions might not yet be available in all the AWS Regions that
  Elastic Beanstalk supports. It might take a few hours for the release to complete.

Updated Docker Compose to version [2.22.0](https://docs.docker.com/compose/release-notes/#2220 "https://docs.docker.com/compose/release-notes/#2220"). Additional changes with the release: <br>• This release adds `--ignore-buildable` to the `docker compose pull` command to prevent an issue with pulling images that need a building process with Docker Compose v2. For more information see [docker compose pull](https://docs.docker.com/engine/reference/commandline/compose_pull/ "https://docs.docker.com/engine/reference/commandline/compose_pull/") in the Docker reference documentation. <br>• This release prevents deployments from being reported as successful if the container does not start up successfully or unexpectedly stops. <br>• This release addresses an issue where the Elastic Beanstalk log file could be appended with duplicate information that's already been logged, on logging restart after the logging process previously failed. <br>• This release limits the amount of times docker compose logging will attempt to restart on failure. |

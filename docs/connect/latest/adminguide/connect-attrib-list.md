## System attributes

These are predefined attributes in Amazon Connect. You can reference system attributes, but you
cannot create them.

Not all blocks in a flow support using System attributes. For example, you cannot use a
System attribute to store customer input. Instead, use a [user-defined attribute](#user-defined-attributes "#user-defined-attributes") to store the data input
by a customer.

                                                                                                    | ## Lambda contact attributes Lambda attributes are returned as key-value pairs from the most recent invocation of an [AWS Lambda function](invoke-lambda-function-block.md "invoke-lambda-function-block.md") block. Lambda invocation attributes are overwritten with each invocation of the Lambda function. To reference attributes in JSONPath, use: <br>• `$.LambdaInvocation.ResultData.attributeName` where `AttributeName` is the attribute name, or the key of the key-value pair returned from the function. For example, if the function returns a contact ID, reference the attribute with `$.LambdaInvocation.ResultData.ContactId`. When referencing a contact ID returned from Amazon Connect, the JSONPath is `$.ContactId`. For more information about using attributes in Lambda functions, see [Grant Amazon Connect access to your AWS Lambda functions](connect-lambda-functions.md "connect-lambda-functions.md"). These attributes are not included in contact records, not passed to the next Lambda invocation, and not passed to the CCP for screenpop information. However, they can be passed as Lambda function inputs on an [AWS Lambda function](invoke-lambda-function-block.md "invoke-lambda-function-block.md") block, or copied to user-defined attributes using the [Set contact attributes](set-contact-attributes.md "set-contact-attributes.md") block. When used in [Set contact attributes](set-contact-attributes.md "set-contact-attributes.md") blocks, the attributes that are copied are included in contact records, and can be used in the CCP. ## User-defined attributes For all other attributes Amazon Connect defines the key and value. For user-defined attributes, however, you provide a name for the key and the value. Use user-defined attributes in situations where you want to store values in a contact flow, and then refer to those values later. For example, if you integrate Amazon Connect and a CRM or other system, you might want to get input from the customer such as their member number. Then you can use that member number retrieve information about the member from the CRM, and/or use the member number throughout the flow, etc. |

Pinpoint [segments](../../../pinpoint/latest/userguide/segments-building.md "../../../pinpoint/latest/userguide/segments-building.md") list to customize experiences in Amazon Connect flows. To reference data in a segment list, use **$.Attributes.`attribute coming in the segment`**. For example, if you have a segment with two columns "Attributes.FirstName" and "Attributes.ItemDescription, you would refer to them as: <br>• $.Attributes.FirstName <br>• $.Attributes.ItemDescription For more information, see [Adding personalized content to message templates](../../../pinpoint/latest/userguide/message-templates-personalizing.md "../../../pinpoint/latest/userguide/message-templates-personalizing.md") in the _Amazon Pinpoint User Guide_. ## Amazon Q in Connect attribute The following attribute stores the Amazon Q in Connect session ARN. A use case for this attribute is when you want to perform any API action, such as [UpdateSession](../APIReference/API_amazon-q-connect_UpdateSession.md "../APIReference/API_amazon-q-connect_UpdateSession.md") [UpdateSessionData](../APIReference/API_amazon-q-connect_UpdateSessionData.md "../APIReference/API_amazon-q-connect_UpdateSessionData.md"). You can pass the attribute as input to [AWS Lambda function](invoke-lambda-function-block.md "invoke-lambda-function-block.md") block. And Lambda can call those APIs against the input session ARN. |

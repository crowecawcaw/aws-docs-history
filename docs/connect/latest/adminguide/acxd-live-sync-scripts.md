

# Live Sync Scripts
<a name="acxd-live-sync-scripts"></a>

Live Sync Scripts let you pair controlled, predefined voice lines with interactions in a web or mobile experience.

Use a Live Sync Script when the wording or sequence should be determined in advance rather than generated dynamically by the Live Sync agent.

For example, while a user completes a checkout experience, a script might say:

"Review your order details, then select **Confirm** to continue."

When the user completes that step in the digital experience, the experience can move to the next scripted voice line or return control to the Live Sync agent.

Live Sync Scripts work alongside Live Sync, Touchpoint, and your agentic CX designer application to create experiences that combine conversational AI with deterministic voice guidance.

Live Sync agents and Live Sync Scripts serve different purposes.

## When to use a Live Sync Script
<a name="acxd-live-sync-scripts-when-to-use"></a>


| Capability | Use it when | 
| --- | --- | 
| Live Sync agent | The experience requires flexible conversation, reasoning, tool use, dynamic responses, or decisions based on the user's request. | 
| Live Sync Script | The experience requires predefined wording or a controlled sequence associated with frontend behavior. | 

Live Sync Scripts are useful when you need:
+ Exact messaging
+ Consistent instructions
+ Controlled legal or compliance language
+ Guided step-by-step experiences
+ Voice prompts synchronized with specific frontend events
+ Predictable transitions back into agentic or deterministic flow behavior

You can combine both approaches in the same experience.

For example, a Live Sync agent can help a customer choose a service plan conversationally. When the customer reaches a required consent step, a Live Sync Script can provide the approved disclosure before the experience continues.

## How Live Sync Scripts work
<a name="acxd-live-sync-scripts-how-it-works"></a>

A Live Sync Script contains a series of predefined voice messages called steps. Each step can be associated with part of your frontend experience so that the appropriate voice line plays when the corresponding event occurs.

A typical experience includes:


| Component | Responsibility | 
| --- | --- | 
| Live Sync Script | Contains the predefined voice lines and step behavior. | 
| Live Sync node | Provides the conversational Live Sync experience and handles script continuation or escalation paths. | 
| Touchpoint SDK | Connects the digital experience to the active Live Sync interaction. | 
| Frontend | Presents the UI and coordinates relevant script behavior with frontend events. | 
| Connect Customer Flow | Provides the active customer interaction and invokes the agentic CX designer application. | 

A simplified experience might look like:

Live Sync conversation → frontend event → scripted voice step → frontend interaction → next scripted step or return to Live Sync

Unlike standard Live Sync agent responses, the wording of a script step is defined by you rather than generated by the LLM.

## Requirements
<a name="acxd-live-sync-scripts-requirements"></a>

Before using a Live Sync Script, configure the broader Live Sync experience.

You typically need:
+ An application
+ A flow containing a Live Sync node
+ A deployed application
+ A Connect Customer flow that invokes the application through the Agentic CX block
+ The Touchpoint SDK integrated with the supported digital experience
+ A Live Sync Script containing the required voice steps
+ A deployed Live Sync Script

Your implementation can determine how users enter the digital experience. For example, a Connect Customer flow might send a link to the customer, but SMS delivery is not inherently required by Live Sync Scripts.

## Create a Live Sync Script
<a name="acxd-live-sync-scripts-create"></a>

**To create a script**

1. Open **Resources** from the workspace menu.

1. Select **Live Sync Scripts**.

1. Create a new script or open an existing script.

1. Select **Add step**.

1. Enter the voice message for the step.

1. Repeat for each predefined step in the experience.

1. Save the script.

Each step represents an authored voice line that can be synchronized with the corresponding frontend experience.

## Write effective script steps
<a name="acxd-live-sync-scripts-write-steps"></a>

Live Sync Scripts work best when each message clearly tells the user what is happening or what they should do next.

Avoid open-ended prompts when the digital experience expects a specific action.

Instead of:

"Would you like to use the card on file?"

Use:

"We can use the card on file. Select **Confirm** to authorize it, or choose another payment method."

The second version tells the user exactly how to interact with the digital experience.

Keep script messages:
+ Short enough to sound natural when spoken
+ Specific to the current UI state
+ Clear about the next expected action
+ Consistent with the controls shown on screen
+ Free of unnecessary conversational filler

Because the wording is predefined, Live Sync Scripts are especially useful when exact phrasing matters.

## Configure step actions
<a name="acxd-live-sync-scripts-step-actions"></a>

Optional actions can be configured for a Script step that provides additional behaviors.

Simply expand a Script step and select **Enable** under **Actions**. Only one action is permitted per step.

### Continue
<a name="acxd-live-sync-scripts-step-actions-continue"></a>

Use **Continue** when the experience should leave the scripted sequence through the Continuation path of the Live Sync node in a flow.

This lets you transition from controlled scripted behavior back into the appropriate flow or agentic experience.

### Escalate
<a name="acxd-live-sync-scripts-step-actions-escalate"></a>

Use **Escalate** when the scripted experience should leave through the Escalation path of the Live Sync node.

For example, a scripted disclosure or verification step might escalate when the experience requires support from a human agent.

The Continuation and Escalation paths on the Live Sync node are specifically used to support Live Sync Script behavior.

### End
<a name="acxd-live-sync-scripts-step-actions-end"></a>

Use **End** when the scripted experience should end the interaction with the agentic CX designer application.

When the experience triggers a step with **End** action enabled, the contact progresses from the Default path of the Agentic CX block on the Connect Customer flow.

## Use Context variables in script messages
<a name="acxd-live-sync-scripts-context-variables"></a>

You can use Context variables to personalize predefined script messages with information already available in the conversation.

For example:

"Thanks, `{customerName}`. Review your updated reservation before continuing."

**To insert a Context variable**

1. Open or add a script step.

1. Select the message field.

1. Enter an opening curly brace {.

1. Select the appropriate Context variable.

1. Save the script.

Make sure the variable is populated in a flow before the script step that references it.

Use Context variables for values such as:
+ Customer name
+ Appointment date
+ Reservation information
+ Account information
+ Previously selected options

This allows the wording to remain controlled while still incorporating relevant customer or session information.

## Add analytics tags
<a name="acxd-live-sync-scripts-analytics-tags"></a>

Assign Analytics tags to important script steps when you want to measure how users progress through the scripted experience.

For example, you might tag:
+ A disclosure step
+ A confirmation step
+ A payment step
+ A successful completion step
+ An escalation step

Use meaningful names that describe the event being measured.

For example:

`payment_confirmation_presented`

or:

`consent_completed`

Analytics tags can help identify where users continue, abandon, or escalate during a guided experience.

## Connect the script to your Live Sync experience
<a name="acxd-live-sync-scripts-connect"></a>

Live Sync Scripts are designed to work as part of an active Live Sync experience.

Configure your agentic CX designer flow with a Live Sync node and connect its relevant paths to the behavior your script requires.

In particular:
+ Use the Continuation path when a script step should transition back into the flow.
+ Use the Escalation path when a script step should trigger escalation behavior.

Your frontend implementation should associate the applicable script steps with the digital events or UI states that should trigger them.

For example:


| Frontend event | Script step | 
| --- | --- | 
| Checkout page opens | "Review your order details before continuing." | 
| Consent panel appears | "Please review the authorization statement shown on screen." | 
| Confirmation succeeds | "Your changes are confirmed." | 
| Additional assistance is required | Escalate from the Live Sync node. | 

This lets the digital experience control when an authored line is appropriate while agentic CX designer controls the surrounding conversational flow.

## Use Live Sync Scripts with Touchpoint
<a name="acxd-live-sync-scripts-touchpoint"></a>

The Touchpoint SDK connects the digital experience to the active Live Sync interaction.

For Live Sync Scripts, your frontend implementation uses Touchpoint as part of the same Live Sync connection used for the broader digital experience.

Touchpoint connection information includes values associated with the deployed application and active customer interaction, such as:
+ Host
+ Deployment key
+ API key
+ Language code
+ Connect Customer contact ID

The Connect Customer contact ID associates the digital experience with the correct active interaction.

Use the current Touchpoint implementation for the Live Sync connection and associate your scripted behavior with the relevant frontend events.

Refer to the Touchpoint SDK documentation for implementation details.

## Combine scripts with agentic Live Sync
<a name="acxd-live-sync-scripts-combine"></a>

Live Sync Scripts do not replace the Live Sync agent. They give you a deterministic option for specific moments within the broader experience.

For example:

The customer says:

"I want to upgrade my internet plan."

The Live Sync agent discusses available options, answers questions, and helps the customer choose a plan.

When the user reaches the final order screen, a Live Sync Script delivers:

"Your new monthly price will be $75. Review the terms shown on screen and select **Accept** to continue."

The wording is fixed rather than generated.

The customer selects **Accept**.

The script uses its continuation behavior and returns control to the appropriate Live Sync flow.

The agent confirms the completed change and continues helping the customer.

1. Agentic conversation

1. Scripted disclosure

1. Frontend confirmation

1. Continue

1. Agentic conversation resumes

This pattern allows you to use generative AI where flexibility is valuable and deterministic messaging where control is more important.

## Deploy a Live Sync Script
<a name="acxd-live-sync-scripts-deploy"></a>

Create and deploy the script before using it in a production Live Sync experience.

From the script's deployment area:

**To deploy a script**

1. Create a build.

1. Review the build status.

1. Resolve any validation or build errors.

1. Deploy the successful build to the appropriate environment.

Script changes should be deployed from the Live Sync Script resource.

Changes to the agentic CX designer application or its flows follow the normal application build and deployment process.

This separation allows you to update scripted messaging without unnecessarily changing unrelated conversational logic.

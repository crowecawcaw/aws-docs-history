# Methods for fine-grained access control

With a data lake, the goal is to have fine-grained access control to data. In Lake Formation, this
means fine-grained access control to Data Catalog resources and Amazon S3 locations. You can achieve
fine-grained access control with one of the following methods.

| Method   | Lake Formation Permissions | IAM Permissions | Comments                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------- | -------------------------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Method 1 | Open                       | Fine-grained    | **This is the default method*<br>• for backward<br>compatibility with AWS Glue.<br>• *Open* means that the special permission<br>`Super` is granted to the group<br>`IAMAllowedPrincipals`, where `IAMAllowedPrincipals` is<br>automatically created and includes any IAM users and roles that are allowed<br>access to your Data Catalog resources by your IAM policies, and the<br>`Super` permission enables a principal to perform every supported<br>Lake Formation operation on the database or table on which it is granted. This<br>effectively causes access to Data Catalog resources and Amazon S3 locations to be<br>controlled solely by IAM policies. For more information, see [Changing the default settings for your data<br>lake](change-settings.md "change-settings.md") and [Upgrading AWS Glue data permissions to<br>the AWS Lake Formation model](upgrade-glue-lake-formation.md "upgrade-glue-lake-formation.md").<br>• *Fine-grained\* means that IAM policies control all<br>access to Data Catalog resources and to individual Amazon S3 buckets.<br>On the Lake Formation console, this method appears as **Use only IAM access<br>control\*\*. |
| Method 2 | Fine-grained               | Coarse-grained  | **This is the recommended method.**<br>• _Fine-grained_ access means granting limited Lake Formation<br>permissions to individual principals on Data Catalog resources, Amazon S3 locations, and<br>the underlying data in those locations.<br>• _Coarse-grained_ means broader permissions on<br>individual operations and on access to Amazon S3 locations. For example, a<br>coarse-grained IAM policy might include `"glue:*"` or<br>`"glue:Create*"` rather than `"glue:CreateTables"`,<br>leaving Lake Formation permissions to control whether or not a principal can create<br>catalog objects. It also means giving principals access to the APIs that they<br>need to do their work, but locking down other APIs and resources. For example,<br>you might create an IAM policy that enables a principal to create Data Catalog<br>resources and create and run workflows, but doesn't enable creation of AWS Glue<br>connections or user-defined functions. See the examples later in this<br>section.                                                                                                                                                             |

###### Important

Be aware of the following:

- By default, Lake Formation has the **Use only IAM access control** settings
  enabled for compatibility with existing AWS Glue Data Catalog behavior. We recommend that you
  disable these settings after you transition to using Lake Formation permissions. For more
  information, see [Changing the default settings for your data
  lake](change-settings.md "change-settings.md").
- Data lake administrators and database creators have implicit Lake Formation permissions that
  you must understand. For more information, see [Implicit Lake Formation permissions](implicit-permissions.md "implicit-permissions.md").

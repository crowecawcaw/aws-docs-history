# Troubleshoot AWS Site-to-Site VPN connectivity without Border Gateway

Protocol

The following diagram and table provide general instructions for troubleshooting a
customer gateway device that does not use Border Gateway Protocol (BGP). We also
recommend that you enable the debug features of your device. Consult your gateway device
vendor for details.

![Flow chart for troubleshooting generic customer gateway device](images/troubleshooting-cgw-flow-nobgp-diagram.png)

|               |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| IKE           | Determine if an IKE security association exists.<br>An IKE security association is required to exchange keys that are<br>used to establish the IPsec security association.<br>If no IKE security association exists, review your IKE<br>configuration settings. You must configure the encryption,<br>authentication, perfect forward secrecy, and mode parameters as<br>listed in the configuration file.<br>If an IKE security association exists, move on to 'IPsec'.                                                                                                                                                                                                                                                                                                                                  |
| IPsec         | Determine if an IPsec security association (SA) exists.<br>An IPsec SA is the tunnel itself. Query your customer gateway<br>device to determine if an IPsec SA is active. Ensure that you<br>configure the encryption, authentication, perfect forward secrecy,<br>and mode parameters as listed in the configuration file.<br>If no IPsec SA exists, review your IPsec configuration.<br>If an IPsec SA exists, move on to 'Tunnel'.                                                                                                                                                                                                                                                                                                                                                                     |
| Tunnel        | Confirm that the required firewall rules are set up (for a list of the rules, see [Firewall rules for an AWS Site-to-Site VPN customer gateway device](FirewallRules.md "FirewallRules.md")). If<br>they are, move forward.<br>Determine if there is IP connectivity through the tunnel.<br>Each side of the tunnel has an IP address as specified in the<br>configuration file. The virtual private gateway address is the<br>address used as the BGP neighbor address. From your customer gateway<br>device, ping this address to determine if IP traffic is being<br>properly encrypted and decrypted.<br>If the ping isn't successful, review your tunnel interface configuration to make sure<br>that the proper IP address is configured.<br>If the ping is successful, move on to 'Static routes'. |
| Static routes | For each tunnel, do the following:<br>• Verify that you have added a static route to your VPC CIDR with the tunnels as the<br>next hop.<br>• Verify that you have added a static route on the<br>Amazon VPC console, to tell the virtual private gateway to route<br>traffic back to your internal networks.<br>If the tunnels are not in this state, review<br>your device configuration.<br>Make sure that both tunnels are in this state, and you're done.                                                                                                                                                                                                                                                                                                                                             |

# Troubleshoot AWS Site-to-Site VPN connectivity when using Border Gateway Protocol

The following diagram and table provide general instructions for troubleshooting a
customer gateway device that uses Border Gateway Protocol (BGP). We also recommend that
you enable the debug features of your device. Consult your gateway device vendor for
details.

![Flow chart for troubleshooting a generic customer gateway device](images/troubleshooting-cgw-flow-diagram.png)

|        |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| IKE    | Determine if an IKE security association exists.<br>An IKE security association is required to exchange keys that are<br>used to establish the IPsec security association.<br>If no IKE security association exists, review your IKE<br>configuration settings. You must configure the encryption,<br>authentication, perfect forward secrecy, and mode parameters as<br>listed in the configuration file.<br>If an IKE security association exists, move on to 'IPsec'.                                                                                                                                                                                                                                                                                                                        |
| IPsec  | Determine if an IPsec security association (SA) exists.<br>An IPsec SA is the tunnel itself. Query your customer gateway<br>device to determine if an IPsec SA is active. Ensure that you<br>configure the encryption, authentication, perfect forward secrecy,<br>and mode parameters as listed in the configuration file.<br>If no IPsec SA exists, review your IPsec configuration.<br>If an IPsec SA exists, move on to 'Tunnel'.                                                                                                                                                                                                                                                                                                                                                           |
| Tunnel | Confirm that the required firewall rules are set up (for a list of the rules, see [Firewall rules for an AWS Site-to-Site VPN customer gateway device](FirewallRules.md "FirewallRules.md")). If<br>they are, move forward.<br>Determine if there is IP connectivity through the tunnel.<br>Each side of the tunnel has an IP address as specified in the<br>configuration file. The virtual private gateway address is the<br>address used as the BGP neighbor address. From your customer gateway<br>device, ping this address to determine if IP traffic is being<br>properly encrypted and decrypted.<br>If the ping isn't successful, review your tunnel interface configuration to make sure<br>that the proper IP address is configured.<br>If the ping is successful, move on to 'BGP'. |
| BGP    | Determine if the BGP peering session is active.<br>For each tunnel, do the following:<br>• On your customer gateway device, determine if the BGP<br>status is `Active` or `Established`.<br>It may take approximately 30 seconds for a BGP peering to<br>become active.<br>• Ensure that the customer gateway device is advertising the<br>default route (0.0.0.0/0) to the virtual private<br>gateway.<br>If the tunnels are not in this state, review<br>your BGP configuration.<br>If the BGP peering is established, you are receiving a prefix, and<br>you are advertising a prefix, your tunnel is configured correctly.<br>Make sure that both tunnels are in this state.                                                                                                                |

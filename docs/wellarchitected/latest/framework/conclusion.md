

# Conclusion

 The AWS Well-Architected Framework provides a consistent way to review, evolve, and operate cloud architectures against a shared set of best practices. Building well-architected systems is not a one-time exercise. Each pillar reinforces the same underlying stance: iterate continuously, base decisions on data, treat every event as a chance to improve, and use AWS services and automation to make the right choice the default choice. 

 The pillars are not independent. A change made for one, such as in cost, security, sustainability, usually shifts the balance in another, which is why the value of applying the framework comes from reviewing all of them together and applying them to a sound organizational foundation. 

## Pillar takeaways
<a name="conclusion-pillar-takeaways"></a>

 The following table summarizes the key takeaway for each area of the framework. 


|  Area  |  Key takeaway  | 
| --- | --- | 
|  Well-Architected Framework  |  The framework spans six pillars and provides a consistent set of review questions and AWS best practices for evaluating an existing or proposed architecture. Applying it helps you produce stable and efficient systems so you can focus on your functional requirements.  | 
|  Cloud Foundations  |  Cloud Foundations gives you the organization-wide controls, standards, and shared services (multi-account structure, identity, observability, resource management, security and compliance, financial management, and networking) that need to be in place before you run production workloads. It is the blueprint for creating a sound landing zone.  | 
|  Operational excellence  |  Operational excellence is ongoing and iterative. Set shared goals across teams, treat every event and failure as an opportunity to learn, and use runbooks, playbooks, operations-as-code, and situational awareness to respond effectively. Prioritize improvements based on changing business needs and lessons from retrospective analysis.  | 
|  Security  |  Security is an ongoing effort throughout your organization and workloads. Strong identity controls, automated response to security events, defense-in-depth across infrastructure layers, and encryption of well-classified data are foundational for every organization. Treat events as opportunities to strengthen the architecture.  | 
|  Reliability  |  Determine the right level of availability for your business, then apply the design, operational, and recovery-oriented practices needed to achieve it. Understanding the trade-offs and matching them to mission-critical needs is the core discipline.  | 
|  Performance efficiency  |  Performance efficiency is data-driven. Understand your access patterns, use benchmarks and load tests to select the right resource types and configurations, treat infrastructure as code so you can evolve safely, and combine active and passive monitoring to catch degradation over time.  | 
|  Cost optimization  |  Cost optimization is a continuous journey that requires collaboration across technology, finance, and business teams. Establish Cloud Financial Management practices, maintain visibility into costs and usage, choose cost-efficient resources, and automate optimization where possible. Balance cost efficiency against the business value the workload delivers.  | 
|  Sustainability  |  Sustainability is now a business driver, and regulation, competitive pressure, and customer and investor expectations all point the same direction. Use the sustainability design principles and AWS services to balance sustainability against the other pillars, and remember that every reduction in resource usage contributes to your organization's broader goals.  | 

## What to do next
<a name="conclusion-what-to-do-next"></a>

 To continue improving your architectures, take the following next steps. 
+  Review a workload against the pillars using the [AWS Well-Architected Tool](https://aws.amazon.com/well-architected-tool/), and evaluate your environment against Well-Architected Foundations before spinning up more workloads on it. 
+  Prioritize improvements that move multiple pillars at once. Automation, for example, improves operational excellence, security, and cost efficiency simultaneously. 
+  Adopt an iterative cadence. Set a review rhythm, capture what you learn from each event and each improvement, and revisit trade-offs as your business needs change. 
+  Bring finance, security, and operations into architecture conversations from the start. 
+  Engage your AWS account team, or use the [AWS Contact Us](https://aws.amazon.com/contact-us/) page, when you want expert input on the trade-offs specific to your workload.

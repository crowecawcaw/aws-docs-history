

# Incident response
<a name="smsec07"></a>

Streaming media incidents include both standard security events and media-specific scenarios such as unauthorized content redistribution. Response plans should cover both.


| SMSEC07: Have your incident responders reviewed processes on how to respond to incidents? | 
| --- | 
| [SMSEC07-BP01 Establish your plan for incident response](smsec07-bp01.md) | 

## Capability intent
<a name="smsec07-intent"></a>
+ Incident response procedures are documented and tested through drills.
+ Escalation paths cover streaming-specific incidents (content leaks, piracy detection).
+ Communication protocols include content licensors where relevant.

## Maturity levels
<a name="smsec07-maturity"></a>


| Level | Name | What it looks like | 
| --- | --- | --- | 
| 1 | Initial | No documented incident response procedures exist. Response is improvised when incidents occur. | 
| 2 | Emerging | Basic procedures are documented but untested. Escalation paths exist for standard security events but not streaming-specific scenarios. | 
| 3 | Defined | Incident response plans cover both standard security events and streaming-specific incidents (content leaks, piracy). Communication protocols include content licensors. | 
| 4 | Proactive | Regular drills and tabletop exercises validate procedures. Escalation from piracy detection to legal action is well-exercised and measured. | 
| 5 | Optimized | Post-incident reviews feed back into procedure improvements. Response times are tracked, and lessons learned are incorporated across the organization. | 

## Common issues to watch for
<a name="smsec07-issues"></a>
+ No documented incident response procedures for streaming-specific scenarios.
+ No escalation path from piracy detection to legal action.
+ No regular drills or tabletop exercises for media security incidents.
+ Outdated infrastructure documentation that slows response during real incidents.

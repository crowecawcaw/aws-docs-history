# Assess source formats and packaging

Consult the following table for information about how to assess the source formats and
packaging. Read across each row.

| Information to obtain                                                                                | Verify the following                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Number of sources that the content provider can provide.                                             | If you plan to implement a [resiliency feature](plan-redundancy.md "plan-redundancy.md"),<br>make sure that your content provider can deliver the required inputs:<br>• For automatic input failover, they must deliver two identical instances of the same<br>source content.<br>• For pipeline redundancy, they must deliver two identical instances of the same source<br>content.<br>• If you plan to implement both features, they must deliver four instances.                                                                                                                                                                                         |
| Delivery formats and protocolsThe type of MediaLive input that applies to the format<br>you identify | Find out what format and protocol the upstream system supports for delivery. Make<br>sure that this format is listed in the table in [Input types, protocols, and upstream systems](inputs-supported-formats.md "inputs-supported-formats.md") .<br>• If the format is listed, identify the MediaLive input type that applies to the<br>format.<br>• If the format isn't listed, speak to your content provider about how they can add<br>support for MediaLive.<br>Note that you don't need to verify this information for content<br>delivered over CDI or content delivered from an AWS Elemental Link. MediaLive can always handle these input<br>types. |
| Whether the upstream system is using the latest SDK                                                  | Make sure that the content provider is using the latest version of the [AWS CDI SDK](https://aws.amazon.com/media-services/resources/cdi/ "https://aws.amazon.com/media-services/resources/cdi/") on their<br>upstream CDI source device.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Whether the source content is a stream or VOD asset                                                  | Find out if the source content is a live stream or a VOD asset.Make sure that<br>MediaLive supports the delivery for the format that you identified. See the table in [Support for live and file sources](inputs-live-vs-file.md "inputs-live-vs-file.md").                                                                                                                                                                                                                                                                                                                                                                                                  |
| Whether the content is encrypted                                                                     | MediaLive can ingest encrypted content only from HLS content.If the source content is<br>HLS and it is encrypted, make sure that it is encrypted in a format that MediaLive supports. See<br>[Handling encrypted source content in<br>an HLS source](planning-hls-input-encrypted.md "planning-hls-input-encrypted.md"). If MediaLive doesn't support the available<br>encryption format, find out if you can obtain the content in unencrypted<br>form.                                                                                                                                                                                                     |
| Only if the source content is RTP, whether it includes FEC.                                          | We recommend that the source content include FEC because it is less likely to result in<br>an output that has visual disruptions.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |



# How Infrastructure Performance works

Network latency measurements are an aggregate of latency performance information captured by active probing between AWS managed probes within the AWS global network. Using Infrastructure Performance, you can view network performance based on the following metrics:
+ Inter-Region latency metrics, generated by aggregating latency measurements from probes located across AWS Regions, filtered on your chosen source and destination Region pairs.
+ Inter-Availability Zone latency metrics, generated by aggregating latency measurements from probes located across Availability Zones, filtered on your chosen source and destination Availability Zones.
+ Intra-Availability Zone latency metrics, generated by aggregating latency measurements between all probes within a single Availability Zone. This includes all probes that are across AWS data centers, and within the same data center, for the chosen Availability Zone.

The placement of the probes isn't related to Amazon EC2 instances or AWS services running in your account. For this reason, the same latency metric data is presented in all AWS accounts.

## How latency is calculated
<a name="CloudWatch-InfrastructurePerformance-How-Latency-Calculated"></a>

Metric data is generated by computing the median (P50) of all latency measurements from AWS managed probes for every five-minute (5M) interval.

Latency metrics represent round-trip traffic latency of synthetic traffic streams between selected sources and destinations. This is a combination of the latency of the underlying physical network and the latency between the host and the underlying physical network.

The Infrastructure Performance dashboard also shows a health status that indicates whether aggregate network latency is normal or degraded, based on expected AWS network performance. Health status is available only for inter-Region and inter-Availability Zone metrics.

**Note**  
If the health status is degraded, AWS is notified automatically.

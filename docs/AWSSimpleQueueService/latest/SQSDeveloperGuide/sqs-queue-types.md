which queue best fits your needs.

| **Unlimited throughput\*<br>• –<br>Standard queues support a very high, nearly unlimited number of API calls per second, per action<br>([`SendMessage`](../APIReference/API_SendMessage.md "../APIReference/API_SendMessage.md"), [`ReceiveMessage`](../APIReference/API_ReceiveMessage.md "../APIReference/API_ReceiveMessage.md"), or [`DeleteMessage`](../APIReference/API_DeleteMessage.md "../APIReference/API_DeleteMessage.md")). This high throughput makes them ideal for use cases that require processing large volumes of messages quickly, such as real-time data streaming or large-scale applications. While standard queues scale automatically with demand, it is essential to monitor usage patterns to ensure optimal performance, especially in regions with higher workloads.<br>**At-least-once delivery*<br>• –<br>Guaranteed at-least-once delivery, meaning that every message is<br>delivered at least once, but in some cases, a message may be delivered<br>more than once due to retries or network delays. You should design your<br>application to handle potential duplicate messages by using idempotent<br>operations, which ensure that processing the same message multiple times<br>will not affect the system’s state.<br>\*\*Best-effort ordering*<br>• –<br>Provides best-effort ordering, meaning that while Amazon SQS attempts to<br>deliver messages in the order they were sent, it does not guarantee<br>this. In some cases, messages may arrive out of order, especially under<br>conditions of high throughput or failure recovery. For applications<br>where the order of message processing is crucial, you should handle<br>reordering logic within the application or use FIFO queues for strict<br>ordering guarantees.<br>**Durability and redundancy\*<br>• –<br>Standard queues ensure high durability by storing multiple copies of<br>each message across multiple AWS Availability Zones. This ensures that<br>messages are not lost, even in the event of infrastructure<br>failures.<br>**Visibility timeout\*<br>• – Amazon SQS<br>allows you to configure a visibility timeout to control how long a<br>message stays hidden after being received, ensuring that other consumers<br>do not process the message until it has been fully handled or the<br>timeout expires. | **High throughput\*<br>• –<br>When you use [batching](sqs-batch-api-actions.md "sqs-batch-api-actions.md"), FIFO queues process up to<br>3,000 messages per second per API method ([`SendMessageBatch`](../APIReference/API_SendMessageBatch.md "../APIReference/API_SendMessageBatch.md"), [`ReceiveMessage`](../APIReference/API_ReceiveMessage.md "../APIReference/API_ReceiveMessage.md"), or [`DeleteMessageBatch`](../APIReference/API_DeleteMessageBatch.md "../APIReference/API_DeleteMessageBatch.md")).<br>This throughput relies on 300 API calls per second, with each API call handling a batch of 10 messages.By enabling high throughput mode, you can scale up to 30,000 transactions per second (TPS) with relaxed ordering within message groups. Without batching, FIFO queues support up to 300 API calls per second per API method (`SendMessage`, `ReceiveMessage`, or `DeleteMessage`). If you need more throughput, you can request a quota increase through the<br>[AWS Support Center](https://console.aws.amazon.com/support/home#/case/create?issueType=service-limit-increase&limitType=service-code-sqs "https://console.aws.amazon.com/support/home#/case/create?issueType=service-limit-increase&limitType=service-code-sqs"). To<br>enable high-throughput mode, see [Enabling high throughput for FIFO queues in<br>Amazon SQS](enable-high-throughput-fifo.md "enable-high-throughput-fifo.md").<br>**Exactly-once processing*<br>• – FIFO<br>queues deliver each message once and keep it available until you process<br>and delete it. By using features like [`MessageDeduplicationId`](../APIReference/API_SendMessage.md "../APIReference/API_SendMessage.md") or content-based<br>deduplication, you prevent duplicate messages, even when retrying due to<br>network issues or timeouts.<br>\*\*First-in-first-out delivery*<br>• –<br>FIFO queues ensure that you receive messages in the order they are sent<br>within each message group. By distributing messages across multiple<br>groups, you can process them in parallel while still maintaining the<br>order within each group. |

| Use standard queues to send data between applications when throughput is<br>crucial, for example:<br>• **Decouple live user requests from<br>intensive background work.\*<br>• Allow users to upload<br>media quickly while you process tasks like resizing or encoding<br>in the background, ensuring fast response times without<br>overloading the system.<br>• **Allocate tasks to multiple worker<br>nodes._<br>• Distribute a high number of credit card<br>validation requests across multiple worker nodes, and handle<br>duplicate messages with idempotent operations to avoid<br>processing errors.<br>• \*\*Batch messages for future<br>processing._<br>• Queue multiple entries for batch<br>additions to a database. Since message order isn’t guaranteed,<br>design your system to handle out-of-order processing if<br>necessary.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Use FIFO queues to send data between applications when the order of<br>events is important, for example:<br>• **Make sure that user-entered commands are<br>run in the right order.\*<br>• This is a key use case<br>for FIFO queues, where command order is crucial. For example, if<br>a user performs a sequence of actions in an application, FIFO<br>queues ensure the actions are processed in the same order they<br>were entered.<br>• **Display the correct product price by<br>sending price modifications in the right order.**<br>FIFO queues ensure that multiple updates to a product's price<br>arrive and are processed sequentially. Without FIFO, a price<br>reduction might be processed after a price increase, causing<br>incorrect data to be displayed.<br>• **Prevent a student from enrolling in a<br>course before registering for an account.\*<br>• By<br>using FIFO queues, you ensure that the registration process<br>occurs in the correct sequence.

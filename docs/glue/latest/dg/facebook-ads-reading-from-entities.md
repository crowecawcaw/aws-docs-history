Partitioning queries You can provide the additional Spark options `PARTITION_FIELD`, `LOWER_BOUND`, `UPPER_BOUND`, and `NUM_PARTITIONS` if you want to utilize concurrency in Spark. With these parameters, the original query would be split into `NUM_PARTITIONS` number of sub-queries that can be executed by Spark tasks concurrently. <br>• `PARTITION_FIELD`: the name of the field to be used to partition the query. <br>• `LOWER_BOUND`: an **inclusive** lower bound value of the chosen partition field. For the DateTime field, we accept the Spark timestamp format used in Spark SQL queries. Example of valid value: `"2022-01-01"` <br>• `UPPER_BOUND`: an **exclusive** upper bound value of the chosen partition field. <br>• `NUM_PARTITIONS`: the number of partitions. Example: `FacebookADs_read = glueContext.create_dynamic_frame.from_options( connection_type="FacebookAds", connection_options={ "connectionName": "connectionName", "ENTITY_NAME": "entityName", "API_VERSION": "v20.0", "PARTITION_FIELD": "created_time" "LOWER_BOUND": "2022-01-01" "UPPER_BOUND": "2024-01-02" "NUM_PARTITIONS": "10" }` |

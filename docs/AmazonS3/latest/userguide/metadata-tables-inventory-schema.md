# S3 Metadata live inventory tables schema

The live inventory table provides a simple, queryable inventory of all the objects and their versions
in your bucket so that you can determine the latest state of your data. Updates to your objects are
typically reflected in the inventory table within one hour.

You can use this table to simplify and speed up business workflows and big data jobs by identifying
objects that you want to process for various workloads. For example, you can query the inventory table to
do the following:

- Find all objects stored in the S3 Glacier Deep Archive storage class.
- Create a distribution of object tags or find objects without tags.
- Find all objects that aren't encrypted by using server-side encryption with AWS Key Management Service (AWS KMS) keys
  (SSE-KMS).
  When you enable the inventory table for your metadata table configuration, the table goes through a
  process known as _backfilling_, during which Amazon S3 scans your general
  purpose bucket to retrieve the initial metadata for all objects in the bucket. Depending on the number of
  objects in your bucket, this process can take minutes (minimum 15 minutes) to hours. When the backfilling process is finished,
  the status of your inventory table changes from **Backfilling** to
  **Active**. After backfilling is completed, updates to your objects are typically
  reflected in the inventory table within one hour.

###### Note

You're charged for backfilling your inventory table. If your general purpose bucket has more than
one billion objects, you're also charged a monthly fee for your inventory table. For more information,
see [Amazon S3 Pricing](https://aws.amazon.com/s3/pricing/ "https://aws.amazon.com/s3/pricing/").

Amazon S3 Metadata inventory tables contain rows and columns. Each row represents the current state of an
object in your general purpose bucket. The inventory table provides a simple, queryable inventory of all
objects in your bucket so that you can determine the current state of your data.

Inventory tables have the following schema:

| Column name             | Required? | Data type                    |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------- | --------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bucket`                | Yes       | String                       | The general purpose bucket name. For more information, see [General purpose bucket naming rules](bucketnamingrules.md "bucketnamingrules.md").                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `key`                   | Yes       | String                       | The object key name (or key) that uniquely identifies the object in the bucket. For more<br>information, see [Naming Amazon S3 objects](object-keys.md "object-keys.md").                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `sequence_number`       | Yes       | String                       | The sequence number, which is an ordinal that's included in the records for a given object.<br>To order records of the same bucket and key, you can sort on `sequence_number`. For a<br>given bucket and key, a lexicographically larger `sequence_number` value implies that<br>the record was introduced to the bucket more recently.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `version_id`            | No        | String                       | The object's version ID. When you enable versioning on a bucket, Amazon S3 assigns a version<br>number to objects that are added to the bucket. For more information, see [Retaining multiple versions of objects with S3 Versioning](Versioning.md "Versioning.md").<br>Objects that are stored in your bucket before you set the versioning state have a version ID<br>of null.                                                                                                                                                                                                                                                                                                                                                                                 |
| `is_delete_marker`      | No        | Boolean                      | The object's delete marker status. If the object is a delete marker, this value is<br>`True`. Otherwise, it's `False`. For more information, see [Working with delete markers](DeleteMarker.md "DeleteMarker.md").<br>NoteRows that are added for delete markers have a `record_type` value of<br>`DELETE`, not `UPDATE_METADATA`. If the delete marker is created as<br>the result of an S3 Lifecycle expiration, the `requester` value is<br>`s3.amazonaws.com`.                                                                                                                                                                                                                                                                                                |
| `size`                  | No        | Long                         | The object size in bytes, not including the size of incomplete multipart uploads or object<br>metadata. If `is_delete_marker` is `True`, the size is `0`. For<br>more information, see [System-defined object metadata](UsingMetadata.md#SysMetadata "UsingMetadata.md#SysMetadata").                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `last_modified_date`    | No        | Timestamp NTZ (no time zone) | The object creation date or the last modified date, whichever is the latest. For multipart<br>uploads, the object creation date is the date when the multipart upload is initiated. For more<br>information, see [System-defined object metadata](UsingMetadata.md#SysMetadata "UsingMetadata.md#SysMetadata").                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `e_tag`                 | No        | String                       | The entity tag (ETag), which is a hash of the object. The ETag reflects changes only to the<br>contents of an object, not to its metadata. The ETag can be an MD5 digest of the object data.<br>Whether the ETag is an MD5 digest depends on how the object was created and how it's encrypted.<br>For more information, see [Object](../API/API_Object.md "../API/API_Object.md") in the _Amazon S3 API<br>Reference_.                                                                                                                                                                                                                                                                                                                                           |
| `storage_class`         | No        | String                       | The storage class that’s used for storing the object. One of `STANDARD`,<br>`REDUCED_REDUNDANCY`, `STANDARD_IA`, `ONEZONE_IA`,<br>`INTELLIGENT_TIERING`, `GLACIER`, `DEEP_ARCHIVE`, or<br>`GLACIER_IR`. For more information, see [Understanding and managing Amazon S3 storage classes](storage-class-intro.md "storage-class-intro.md").                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `is_multipart`          | No        | Boolean                      | The object's upload type. If the object was uploaded as a multipart upload, this value is<br>`True`. Otherwise, it's `False`. For more information, see [Uploading and copying objects using multipart upload in Amazon S3](mpuoverview.md "mpuoverview.md").                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `encryption_status`     | No        | String                       | The object's server-side encryption status, depending on what kind of encryption key is<br>used: server-side encryption with Amazon S3 managed keys (SSE-S3), server-side encryption with<br>AWS Key Management Service (AWS KMS) keys (SSE-KMS), dual-layer server-side encryption with AWS KMS keys<br>(DSSE-KMS), or server-side encryption with customer-provided keys (SSE-C). If the object is<br>unencrypted, this value is null. Possible values are `SSE-S3`, `SSE-KMS`,<br>`DSSE-KMS`, `SSE-C`, or null. For more information, see [Protecting data with encryption](UsingEncryption.md "UsingEncryption.md").                                                                                                                                          |
| `is_bucket_key_enabled` | No        | Boolean                      | The object's S3 Bucket Key enablement status. If the object uses an S3 Bucket Key for<br>SSE-KMS, this value is `True`. Otherwise, it's `False`. For more<br>information, see [Configuring an S3 Bucket Key at the object<br>level](configuring-bucket-key-object.md "configuring-bucket-key-object.md").                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `kms_key_arn`           | No        | String                       | The Amazon Resource Name (ARN) for the KMS key with which the object is encrypted, for rows<br>where `encryption_status` is `SSE-KMS` or `DSSE-KMS`. If the<br>object isn't encrypted with SSE-KMS or DSSE-KMS, the value is null. For more information, see<br>[Using server-side encryption with AWS KMS keys<br>(SSE-KMS)](UsingKMSEncryption.md "UsingKMSEncryption.md") and [Using dual-layer server-side encryption with AWS KMS keys<br>(DSSE-KMS)](UsingDSSEncryption.md "UsingDSSEncryption.md").<br>NoteIf a row represents an object version that no longer existed at the time that a delete or<br>overwrite event was processed, `kms_key_arn` contains a null value, even if the<br>`encryption_status` column value is `SSE-KMS` or<br>`DSSE-KMS`. |
| `checksum_algorithm`    | No        | String                       | The algorithm that’s used to create the checksum for the object, one of<br>`CRC64-NVME`, `CRC32`, `CRC32C`, `SHA1`, or<br>`SHA256`. If no checksum is present, this value is null. For more information, see<br>[Using supported checksum algorithms](checking-object-integrity-upload.md#using-additional-checksums "checking-object-integrity-upload.md#using-additional-checksums").                                                                                                                                                                                                                                                                                                                                                                           |
| `object_tags`           | No        | Map <String, String>         | The object tags that are associated with the object. Object tags are stored as a map of<br>key-value pairs. If an object has no object tags, an empty map (`{}`) is stored. For<br>more information, see [Categorizing your objects using tags](object-tagging.md "object-tagging.md").<br>NoteIf the `record_type` value is `DELETE`, the `object_tags`<br>column contains a null value. If the `record_type` value is `CREATE` or<br>`UPDATE_METADATA`, rows that represent object versions that no longer existed at<br>the time that a delete or overwrite event was processed will contain a null value in the<br>`object_tags` column.                                                                                                                      |
| `user_metadata`         | No        | Map <String, String>         | The user metadata that's associated with the object. User metadata is stored as a map of<br>key-value pairs. If an object has no user metadata, an empty map (`{}`) is stored.<br>For more information, see [User-defined object metadata](UsingMetadata.md#UserMetadata "UsingMetadata.md#UserMetadata").<br>NoteIf the `record_type` value is `DELETE`, the<br>`user_metadata` column contains a null value. If the `record_type`<br>value is `CREATE` or `UPDATE_METADATA`, rows that represent object<br>versions that no longer existed at the time that a delete or overwrite event was processed<br>will contain a null value in the `user_metadata` column.                                                                                               |

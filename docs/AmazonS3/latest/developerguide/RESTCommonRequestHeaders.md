# Common request headers

The following table describes headers that can be used by various types of Amazon S3 REST
requests.

| Header Name                     | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Authorization`                 | The information required for request authentication. For more information, go to [The Authentication Header](../userguide/RESTAuthentication.md#ConstructingTheAuthenticationHeader "../userguide/RESTAuthentication.md#ConstructingTheAuthenticationHeader") in the _Amazon Simple<br>Storage Service Developer Guide_. For anonymous requests<br>this header is not required.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `Access-Control-Request-Method` | A list of HTTP methods that is sent as a pre-flight CORS request. If the pre-flight CORS<br>evaluation is successful, then the specified methods are allowed to be used<br>in the following CORS request.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `Content-Length`                | Length of the message (without the headers) according to RFC 2616. This header is<br>required for PUTs and operations that load XML, such as logging and<br>ACLs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `Content-Type`                  | The content type of the resource in case the request has content in the body. Example:<br>`text/plain`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `Content-MD5`                   | The base64 encoded 128-bit MD5 digest of the message (without the headers) according to<br>RFC 1864. This header can be used as a message integrity check to verify<br>that the data is the same data that was originally sent. Although it is<br>optional, we recommend using the Content-MD5 mechanism as an end-to-end<br>integrity check. For more information about REST request authentication,<br>go to [REST Authentication](../userguide/RESTAuthentication.md "../userguide/RESTAuthentication.md") in the _Amazon Simple Storage<br>Service Developer Guide_.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `Date`                          | The date that can be used to create the signature contained in the<br>`Authorization` header. If the `Date` header<br>is to be used for signing it must be specified in the ISO 8601 basic<br>format. In this case, the `x-amz-date` header is not needed.<br>Note that when `x-amz-date` is present, it always overrides<br>the value of the `Date` header.<br>If the Date header is not used for signing, it can be one of the full<br>date formats specified by [RFC<br>2616](http://tools.ietf.org/html/rfc2616#section-3.3 "http://tools.ietf.org/html/rfc2616#section-3.3"), section 3.3. For example, the date/time<br>`Wed, 01 Mar 2006 12:00:00 GMT` is a valid date/time header for use with<br>Amazon S3.<br>If you are using the `Date` header for signing, then it<br>must be in the ISO 8601 basic `YYYYMMDD'T'HHMMSS'Z'` format.<br>If `Date` is specified but is not in ISO 8601 basic format, then<br>you must also include the `x-amz-date` header. If<br>`Date` is specified in ISO 8601 basic format, then this<br>is sufficient for signing requests and you do not need the<br>`x-amz-date` header. For more information, see [Handling Dates in Signature Version 4](../../../general/latest/gr/sigv4-date-handling.md "../../../general/latest/gr/sigv4-date-handling.md") in the<br>_Amazon Web Services Glossary_. |
| `Expect`                        | When your application uses 100-continue, it does not send the request body until it<br>receives an acknowledgment. If the message is rejected based on the<br>headers, the body of the message is not sent. This header can be used<br>only if you are sending a body.<br>Valid Values: 100-continue                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `Host`                          | For path-style requests, the value is `s3.amazonaws.com`. For<br>virtual-style requests, the value is `BucketName.s3.amazonaws.com`. For more information, go to<br>[Virtual Hosting](../userguide/VirtualHosting.md "../userguide/VirtualHosting.md") in the _Amazon Simple Storage Service User Guide_.<br>This header is required for HTTP 1.1 (most toolkits add this header automatically);<br>optional for HTTP/1.0 requests.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `Origin`                        | An endpoint that specifies the server name of the initial requester.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `x-amz-content-sha256`          | When using signature version 4 to authenticate request, this header provides a hash of<br>the request payload. For more information see [Signature Calculations for the Authorization Header: Transferring Payload in a Single Chunk (AWS Signature Version 4)](sig-v4-header-based-auth.md "sig-v4-header-based-auth.md"). When uploading object in<br>chunks, you set the value to `STREAMING-AWS4-HMAC-SHA256-PAYLOAD` to<br>indicate that the signature covers only headers and that there is no<br>payload. For more information, see [Signature Calculations for the Authorization Header: Transferring Payload in Multiple Chunks (Chunked Upload) (AWS Signature Version 4)](sigv4-streaming.md "sigv4-streaming.md").                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `x-amz-date`                    | The date used to create the signature in the Authorization header. The format must be<br>ISO 8601 basic in the `YYYYMMDD'T'HHMMSS'Z'` format. For<br>example, the date/time `20170210T120000Z` is a valid<br>`x-amz-date` for use with Amazon S3.<br>`x-amz-date` is optional for all requests; it can be used to<br>override the date used for signing requests. If the `Date`<br>header is specified in the ISO 8601 basic format, then<br>`x-amz-date` is not needed. When `x-amz-date`<br>is present, it always overrides the value of the `Date`<br>header. For more information, see [Handling Dates in Signature Version 4](../../../general/latest/gr/sigv4-date-handling.md "../../../general/latest/gr/sigv4-date-handling.md") in the<br>_Amazon Web Services Glossary_.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `x-amz-security-token`          | This header can be used in the following scenarios:<br>• To provide security tokens for Amazon DevPay operations - Each request that uses Amazon DevPay requires<br>two `x-amz-security-token` headers: one for the<br>product token and one for the user token. When Amazon S3 receives an<br>authenticated request, it compares the computed signature with<br>the provided signature. Improperly formatted multi-value headers<br>that are used to calculate a signature can cause authentication<br>issues.<br>• To provide a security token when using temporary security credentials - When making<br>requests using temporary security credentials that you obtained<br>from IAM, you must provide a security token by using this<br>header. To learn more about temporary security credentials, see<br>[Making<br>Requests](../userguide/MakingRequests.md "../userguide/MakingRequests.md").<br>This header is required for requests that use Amazon DevPay and requests that are signed by using<br>temporary security credentials.                                                                                                                                                                                                                                                                                                |

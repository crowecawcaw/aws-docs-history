# AWS Elemental MediaConnect

metrics to monitor flow health

AWS Elemental MediaConnect sends metrics to CloudWatch. You can review specific metrics to
evaluate the health of your flow. If the flow is unhealthy, these metrics can help
you determine where the issue originates. For details about each metric, see the
tables in this section.

For information about source metrics, see [Metrics
to monitor flow source health](monitor-with-cloudwatch-metrics-source-health.md "monitor-with-cloudwatch-metrics-source-health.md").

###### Note

Metrics tracked by MediaConnect adhere to the standard as defined by the TR
101 290 spec.

## Flow

metrics

The following table lists network metrics that AWS Elemental MediaConnect sends to
CloudWatch.

| Metric                | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ARQRecovered`        | The number of dropped packets that were recovered by<br>automatic repeat request (ARQ). This metric doesn't apply to<br>flows that receive content from an entitlement or to flows<br>that have multiple sources. For flows that have multiple<br>sources, use the SourceARQRecovered metric to view data for<br>each source.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                               |
| `ARQRequests`         | The number of retransmitted packets that were requested<br>through automatic repeat request (ARQ) and received. This<br>metric doesn't apply to flows that receive content from an<br>entitlement or to flows that have multiple sources. For<br>flows that have multiple sources, use the SourceARQRequests<br>metric to view data for each source.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                        |
| `BitRate`             | The bitrate of the incoming (source) video.<br>Units: bits per second (bps)<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                                                                                                                                                                                                 |
| `Connected`           | The status of the source. A value of 1 indicates that the<br>source is connected and a value of 0 (zero) indicates that<br>the source is disconnected. This metric applies only to<br>sources that use the Zixi, SRT, or RIST protocols.<br>Units: None<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                     |
| `Disconnections`      | The number of times that the source status changed from<br>connected to disconnected.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                                                                                                                                                                       |
| `DroppedPackets`      | The number of packets that were lost during transit. This<br>value is measured before any error correction takes<br>place.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                                                                                                                                  |
| `FECPackets`          | The number of packets that were transmitted using forward<br>error correction (FEC) and received. This metric applies<br>only to flows that have one source that uses the RTP-FEC or<br>Zixi protocols. It doesn't apply to flows that receive<br>content from an entitlement or to flows that have multiple<br>sources. For flows that have multiple sources, use the<br>SourceFECPackets metric to view data for each source.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                             |
| `FECRecovered`        | The number of packets that were transmitted using forward<br>error correction (FEC), lost during transit, and recovered.<br>This metric applies only to flows that have one source that<br>uses the RTP-FEC or Zixi protocols. It doesn't apply to<br>flows that receive content from an entitlement or to flows<br>that have multiple sources. For flows that have multiple<br>sources, use the SourceFECRecovered metric to view data for<br>each source.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows |
| `MergeActive`         | The merge status of all sources on the flow. A value of 1<br>indicates that all sources are merged. A value of 0 (zero)<br>indicates that at least one source is not actively merged<br>with 2022-7.<br>Units: None<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                                                         |
| `MergeLatency`        | The maximum value for SourceMergeLatency.<br>Units: Milliseconds<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                                                                                                                                                                                                            |
| `NotRecoveredPackets` | The number of packets that were lost during transit and<br>were not recovered by error correction.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                                                                                                                                                          |
| `OverflowPackets`     | The number of packets that were lost in transit because<br>the video required more buffer than was available. This<br>metric doesn't apply to flows that receive content from an<br>entitlement or to flows that have multiple sources.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                     |
| `PacketLossPercent`   | The percentage of packets that were lost during transit,<br>even if they were recovered.<br>Units: Percent<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                                                                                                                                                                  |
| `RecoveredPackets`    | The number of packets that were lost during transit, but<br>recovered.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                                                                                                                                                                                      |
| `RoundTripTime`       | The amount of time it takes for the source to send a<br>signal and receive an acknowledgment from AWS Elemental MediaConnect.<br>This metric doesn't apply to flows that receive content from<br>an entitlement or to flows that have multiple sources. For<br>flows that have multiple sources, use the<br>SourceRoundTripTime metric to view data for each<br>source.<br>Units: Milliseconds<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                              |
| `TotalPackets`        | The total number of packets that were received.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                                                                                                                                                                                                             |
| `FailoverSwitches`    | The total number of times the flow switches back and forth<br>between sources when using the \*Failover<br>• mode for source failover.                                                                                                                                                                                                                                                                                                                                                                                                               |

## TR 101 290

Priority 1 metrics

The following table lists TR 101 290 Priority 1 metrics that AWS Elemental MediaConnect
sends to CloudWatch.

| Metric              | Description                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ContinuityCounter` | The number of times that a continuity error occurred. This<br>error indicates an incorrect packet order or lost<br>packets.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                     |
| `PATError`          | The number of times that a program association table (PAT)<br>error occurred. This error indicates that the PAT is<br>missing. The PAT lists the programs that are available in a<br>transport stream (TS) and points to the program map tables<br>(PMTs). The decoder needs the PAT to do its job.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                             |
| `PIDError`          | The number of times that a packet identifier (PID) error<br>occurred. This error indicates that a PID is missing its<br>associated data stream. The PIDs are identifiers that<br>provide the location of the video, audio, and data streams.<br>This error can occur after the transport stream has been<br>multiplexed and then remultiplexed.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows |
| `PMTError`          | The number of times that a program map table (PMT) error<br>occurred. This error happens when the PMT is not received at<br>least every 500 milliseconds (ms). Each PMT contains a list<br>of PIDs, which help decoders reassemble data. The decoder<br>needs the PMTs to do its job.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                           |
| `TSByteError`       | The number of times that a transport stream byte error<br>occurred. This error indicates that the sync byte did not<br>appear after the prescribed number of bytes.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                             |
| `TSSyncLoss`        | The number of times that a TS sync loss error occurred.<br>This error happens after two or more consecutive TS byte<br>errors.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                  |

## TR 101 290

Priority 2 metrics

The following table lists TR 101 290 Priority 2 metrics that AWS Elemental MediaConnect
sends to CloudWatch.

| Metric             | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CATError`         | The number of times that a conditional access table (CAT)<br>error occurred. This error indicates that the CAT is not<br>present. The CAT tells the integrated receiver decoder (IRD)<br>where to find management messages for the conditional access<br>(CA) systems that are in use.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                       |
| `CRCError`         | The number of times that a cyclic redundancy check (CRC)<br>error occurred. This error happens when a CRC determines<br>that data is corrupted.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                                                              |
| `PCRAccuracyError` | The number of times that a program clock register (PCR)<br>accuracy error occurred. This error happens when the value<br>of the transmitted PCR differs from what is expected by more<br>than 500 nanoseconds (ns). When a stream is encoded, the<br>encoder assigns periodic PCR values of the encoder's program<br>clock. The decoder relies on these values to ensure that the<br>stream is kept in sync.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows |
| `PCRError`         | The number of times that a PCR error occurred. This error<br>happens when PCR values are not sent frequently enough. The<br>service relies on consistent, frequent PCRs to reset the<br>local 27 MHz system clock. Although the error occurs when<br>the interval exceeds 100 milliseconds (ms), best practices<br>dictate that PCRs should be received at least every 40 ms.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                |
| `PTSError`         | The number of times that a presentation timestamp (PTS)<br>error occurred. This error happens when a presentation<br>timestamp (PTS) is not received at least every 700 ms. This<br>can occur if the PTS is sent less frequently or not at all.<br>The most common cause of this error is when the transport<br>stream (TS) is scrambled.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                    |
| `TransportError`   | The number of times that a primary transport error<br>occurred. This error indicates that the TS packet is<br>unusable. When this error occurs, ignore all other TR 101<br>290 errors for this packet.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                       |

| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MaintenanceScheduled`   | Maintenance is scheduled for the flow.<br>Units: Count<br>Valid dimensions:<br>• Flow ARN<br>• All flows                                                                                                                                                        |
| `MaintenanceRescheduled` | MediaConnect is unable to perform maintenance at the previously<br>scheduled date and time. A new date and time has been<br>automatically assigned by MediaConnect for this flow's<br>maintenance.Units: CountValid<br>dimensions:<br>• Flow ARN<br>• All flows |
| `MaintenanceCanceled`    | Maintenance for this flow is cancelled by MediaConnect.Units:<br>CountValid dimensions:<br>• Flow ARN<br>• All flows                                                                                                                                            |
| `MaintenanceStarted`     | Maintenance has started and is currently in progress for this<br>flow.Units: CountValid dimensions:<br>• Flow ARN<br>• All flows                                                                                                                                |
| `MaintenanceSucceeded`   | Maintenance completed successfully for this flow.Units:<br>CountValid dimensions:<br>• Flow ARN<br>• All flows                                                                                                                                                  |
| `MaintenanceFailed`      | Maintenance did not complete successfully for this<br>flow.Units: CountValid dimensions:<br>• Flow ARN<br>• All flows                                                                                                                                           |

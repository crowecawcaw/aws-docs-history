# AWS Elemental MediaConnect

metrics to monitor flow source health

AWS Elemental MediaConnect sends metrics to CloudWatch. You can review specific metrics to
evaluate the health of the source of your flow. If the flow is unhealthy, these
metrics can help you determine whether the issue originates with the source. For
details about each metric, see the tables in this section.

For information about flow metrics, see [Metrics to
monitor flow health](monitor-with-cloudwatch-metrics-flow-health.md "monitor-with-cloudwatch-metrics-flow-health.md").

###### Note

Metrics tracked by MediaConnect adhere to the standard as defined by the TR
101 290 spec.

## TR 101 290

Priority 1 metrics

The following table lists TR 101 290 Priority 1 metrics that AWS Elemental MediaConnect
sends to CloudWatch.

These metrics apply only to transport stream protocols.

| Metric                    | Description                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `SourceContinuityCounter` | The number of times that a continuity error occurred. This<br>error indicates an incorrect packet order or lost<br>packets.<br>Units: Count<br>Valid dimensions:<br>• Source ARN<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                       |
| `SourcePATError`          | The number of times that a program association table (PAT)<br>error occurred. This error indicates that the PAT is<br>missing. The PAT lists the programs that are available in a<br>transport stream (TS) and points to the program map tables<br>(PMTs). The decoder needs the PAT to do its job.<br>Units: Count<br>Valid dimensions:<br>• Source ARN<br>• Flow ARN<br>• Availability Zone<br>• All flows                               |
| `SourcePIDError`          | The number of times that a packet identifier (PID) error<br>occurred. This error indicates that a PID is missing its<br>associated data stream. The PIDs are identifiers that<br>provide the location of the video, audio, and data streams.<br>This error can occur after the TS has been multiplexed and<br>then remultiplexed.<br>Units: Count<br>Valid dimensions:<br>• Source ARN<br>• Flow ARN<br>• Availability Zone<br>• All flows |
| `SourcePMTError`          | The number of times that a program map table (PMT) error<br>occurred. This error happens when the PMT is not received at<br>least every 500 milliseconds (ms). Each PMT contains a list<br>of PIDs, which help decoders reassemble data. The decoder<br>needs the PMTs to do its job.<br>Units: Count<br>Valid dimensions:<br>• Source ARN<br>• Flow ARN<br>• Availability Zone<br>• All flows                                             |
| `SourceTSByteError`       | The number of times that a TS byte error occurred. This<br>error indicates that the sync byte did not appear after the<br>prescribed number of bytes.<br>Units: Count<br>Valid dimensions:<br>• Source ARN<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                             |
| `SourceTSSyncLoss`        | The number of times that a TS sync loss error occurred.<br>This error happens after two or more consecutive TS byte<br>errors.<br>Units: Count<br>Valid dimensions:<br>• Source ARN<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                    |

## TR 101 290

Priority 2 metrics

The following table lists TR 101 290 Priority 2 metrics that AWS Elemental MediaConnect
sends to CloudWatch.

These metrics apply only to transport stream protocols.

| Metric                   | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SourceCATError`         | The number of times that a conditional access table (CAT)<br>error occurred. This error indicates that the CAT is not<br>present. The CAT tells the integrated receiver decoder (IRD)<br>where to find management messages for the conditional access<br>(CA) systems that are in use.<br>Units: Count<br>Valid dimensions:<br>• Source ARN<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                         |
| `SourceCRCError`         | The number of times that a cyclic redundancy check (CRC)<br>error occurred. This error happens when a CRC determines<br>that data is corrupted.<br>Units: Count<br>Valid dimensions:<br>• Source ARN<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                                                                                |
| `SourcePCRAccuracyError` | The number of times that a program clock register (PCR)<br>accuracy error occurred. This error happens when the value<br>of the transmitted PCR differs from what is expected by more<br>than 500 nanoseconds (ns). When a stream is encoded, the<br>encoder assigns periodic PCR values from the encoder's<br>program clock. The decoder relies on these values to ensure<br>that the stream is kept in sync.<br>Units: Count<br>Valid dimensions:<br>• Source ARN<br>• Flow ARN<br>• Availability Zone<br>• All flows |
| `SourcePCRError`         | The number of times that a PCR error occurred. This error<br>happens when PCR values are not sent frequently enough. The<br>service relies on consistent, frequent PCRs to reset the<br>local 27 MHz system clock. Although the error occurs when<br>the interval exceeds 100 milliseconds (ms), best practices<br>dictate that PCRs should be received at least every 40 ms.<br>Units: Count<br>Valid dimensions:<br>• Source ARN<br>• Flow ARN<br>• Availability Zone<br>• All flows                                  |
| `SourcePTSError`         | The number of times that a presentation timestamp (PTS)<br>error occurred. This error happens when a presentation<br>timestamp (PTS) is not received at least every 700 ms. This<br>can occur if the PTS is sent less frequently or not at all.<br>The most common cause of this error is when the TS is<br>scrambled.<br>Units: Count<br>Valid dimensions:<br>• Source ARN<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                         |
| `SourceTransportError`   | The number of times that a primary transport error<br>occurred. This error indicates that the TS packet is<br>unusable. When this error occurs, ignore all other TR 101<br>290 errors for this packet.<br>Units: Count<br>Valid dimensions:<br>• Source ARN<br>• Flow ARN<br>• Availability Zone<br>• All flows                                                                                                                                                                                                         |

# Using a snapshot to migrate data

In-place upgrades are the easier, faster, and more reliable way to upgrade a domain to
a later OpenSearch or Elasticsearch version. Snapshots are a good option if you need to
migrate from a pre-5.1 version of Elasticsearch or want to migrate to an entirely new
cluster.

The following table shows how to use snapshots to migrate data to a domain that uses a
different OpenSearch or Elasticsearch version. For more information about taking and
restoring snapshots, see [Creating index snapshots in Amazon OpenSearch Service](managedomains-snapshots.md "managedomains-snapshots.md").

| OpenSearch 1.3 or 2._x_           | OpenSearch 2._x_    | 1. Review breaking changes for OpenSearch 2.3 to see if you<br>need to make adjustments to your indexes or applications.<br>2. Create a manual snapshot of the 1.3 or 2.*x<br>• domain.<br>3. Create a 2.*x<br>• domain<br>that's a higher version than your original 1.3 or<br>2.*x<br>• domain.<br>4. Restore the snapshot from the original domain to the<br>2.*x<br>• domain. During<br>the operation, you might need to restore your<br>`.opensearch` index under a new name:<br>``<br>POST _snapshot/`<repository-name>`/`<snapshot-name>`/_restore<br>{<br>"indices": "*",<br>"ignore_unavailable": true,<br>"rename_pattern": ".opensearch",<br>"rename_replacement": ".backup-opensearch"<br>}<br>``<br>Then you can reindex `.backup-opensearch` on<br>the new domain and alias it to `.opensearch`.<br>Note that the `_restore` REST call doesn't<br>include `include_global_state` because the<br>default in `_restore` is false. As a result, the<br>test domain won't include any index templates and won't have<br>the full state from the backup.<br>5. If you no longer need your original domain, delete it.<br>Otherwise, you continue to incur charges for the<br>domain. |



# Camera as a Service
<a name="camera-as-a-service"></a>

Publication date: **January 25, 2023 ([Diagram history](#caas-history))**

With this architecture, you can use Internet of Things (IoT)-enabled cameras to generate live video feed and machine learning (ML) inference that you can consume in near real-time. The solution uses [Amazon Kinesis Video Streams](https://docs.aws.amazon.com/kinesisvideostreams/latest/dg/), [Amazon Rekognition](https://docs.aws.amazon.com/rekognition/latest/dg/), [Amazon Elastic Kubernetes Service](https://docs.aws.amazon.com/eks/latest/userguide/) (Amazon EKS), and [Amazon API Gateway](https://docs.aws.amazon.com/apigateway/latest/developerguide/).

## Camera as a service diagram
<a name="caas-diagram"></a>

![Reference architecture diagram for generating live video feed and machine learning inference from IoT-enabled cameras by using Kinesis Video Streams, Amazon Rekognition, Amazon EKS, API Gateway, and DynamoDB.](http://docs.aws.amazon.com/reference-architecture-diagrams/latest/camera-as-a-service/images/camera-as-a-service-ra.png)


The following steps describe the architecture:

1. Generate video feed by using Amazon Kinesis Video Streams Producer libraries.

1. Ingest live video feed to Amazon Kinesis Video Streams.

1. Convert the live feed into images through an on-demand or automated feature and send the images to [Amazon Simple Storage Service](https://docs.aws.amazon.com/AmazonS3/latest/userguide/) (Amazon S3).

1. An Amazon S3 write event invokes a [AWS Lambda](https://docs.aws.amazon.com/lambda/latest/dg/) function. The function sends the image to Amazon Rekognition to generate inference.

1. Store the inference and metadata in [Amazon DynamoDB](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/).

1. Use APIs to fetch the inference from DynamoDB.

1. The user app consumes live feed from Kinesis Video Streams, fetches inference from DynamoDB, and exposes the live feed by using a REST API. The user app runs on Amazon EKS.

1. API Gateway exposes the API for video feed and inference.

1. The end user consumes two APIs from API Gateway. The first provides video feed by using HTTP Live Streaming (HLS), [MPEG-DASH](https://ottverse.com/mpeg-dash-video-streaming-the-complete-guide/), or GetMedia streaming. The second provides the ML inference.

1. The admin app on Amazon EKS handles governance, administrative APIs, user APIs, camera onboarding, metrics, and insights.

1. Use [Amazon CloudWatch](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/) to store logs and metrics from the complete stack. Use [Amazon Cognito](https://docs.aws.amazon.com/cognito/latest/developerguide/) to secure the API feed generated by API Gateway.

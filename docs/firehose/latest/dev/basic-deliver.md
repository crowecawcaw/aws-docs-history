# Understand data delivery in Amazon Data Firehose

When you send data to your Firehose stream, it's automatically delivered to your chosen destination. The following table explains data delivery to different destinations.

| Destination                                  | Details                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Amazon S3                                    | For data delivery to Amazon S3, Firehose concatenates multiple incoming<br>records based on the buffering configuration of your Firehose stream. It then<br>delivers the records to Amazon S3 as an Amazon S3 object. By default, Firehose<br>concatenates data without any delimiters. If you want to have new line<br>delimiters between records, you can add new line delimiters by enabling<br>the feature in the [Firehose console configuration](create-destination.md#create-destination-s3 "create-destination.md#create-destination-s3") or [API<br>parameter](../APIReference/API_Processor.md "../APIReference/API_Processor.md"). Data delivery between Firehose and Amazon S3 destination<br>is encrypted with TLS (HTTPS).                                                                                                                                                                                                                                                                                                                                                                        |
| Amazon Redshift                              | For data delivery to Amazon Redshift, Firehose first delivers incoming data to your<br>S3 bucket in the format described earlier. Firehose then issues an Amazon Redshift<br>\*_COPY_<br>• command to load the data from your S3 bucket<br>to your Amazon Redshift provisioned cluster or Amazon Redshift Serverless workgroup. Ensure<br>that after Amazon Data Firehose concatenates multiple incoming records to an Amazon S3<br>object, the Amazon S3 object can be copied to your Amazon Redshift provisioned cluster<br>or Amazon Redshift Serverless workgroup. For more information, see<br>[Amazon Redshift COPY Command Data Format Parameters](../../../redshift/latest/dg/copy-parameters-data-format.md "../../../redshift/latest/dg/copy-parameters-data-format.md").                                                                                                                                                                                                                                                                                                                             |
| OpenSearch Service and OpenSearch Serverless | For data delivery to OpenSearch Service and OpenSearch Serverless,<br>Amazon Data Firehose buffers incoming records based on the buffering configuration of<br>your Firehose stream. It then generates an OpenSearch Service or OpenSearch<br>Serverless bulk request to index multiple records to your OpenSearch Service<br>cluster or OpenSearch Serverless collection. Make sure that your record is<br>UTF-8 encoded and flattened to a single-line JSON object before you send it<br>to Amazon Data Firehose. Also, the `rest.action.multi.allow_explicit_index`<br>option for your OpenSearch Service cluster must be set to true (default) to<br>take bulk requests with an explicit index that is set per record. For more<br>information, see [OpenSearch Service Configure Advanced Options](../../../opensearch-service/latest/developerguide/es-createupdatedomains.md#es-createdomain-configure-advanced-options "../../../opensearch-service/latest/developerguide/es-createupdatedomains.md#es-createdomain-configure-advanced-options") in the<br>_Amazon OpenSearch Service Developer Guide_. |
| Splunk                                       | For data delivery to Splunk, Amazon Data Firehose concatenates the bytes that you<br>send. If you want delimiters in your data, such as a new line character,<br>you must insert them yourself. Make sure that Splunk is configured to<br>parse any such delimiters. To redrive the data that was delivered to S3<br>error bucket (S3 backup) back to Splunk, follow the steps mentioned in<br>the [Splunk documentation](https://www.splunk.com/en_us/blog/tips-and-tricks/aws-technical-add-on-simplifying-error-data-re-ingestion.html "https://www.splunk.com/en_us/blog/tips-and-tricks/aws-technical-add-on-simplifying-error-data-re-ingestion.html").                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| HTTP endpoint                                | For data delivery to an HTTP endpoint owned by a supported third-party<br>service provider, you can use the integrated Amazon Lambda service to create<br>a function to transform the incoming record(s) to the format that matches<br>the format the service provider's integration is expecting. Contact the<br>third-party service provider whose HTTP endpoint you've chosen for your<br>destination to learn more about their accepted record format.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Snowflake                                    | For data delivery to Snowflake, Amazon Data Firehose internally buffers data for<br>one second and uses Snowflake streaming API operations to insert data to<br>Snowflake. By default, records that you insert are flushed and committed<br>to the Snowflake table every second. After you make the insert call,<br>Firehose emits a CloudWatch metric that measures how long it took for the data to<br>be committed to Snowflake. Firehose currently supports only single JSON<br>item as record payload and doesn’t support JSON arrays. Make sure that<br>your input payload is a valid JSON object and is well formed without any<br>extra double quotes, quotes, or escape characters.                                                                                                                                                                                                                                                                                                                                                                                                                    |

Each Firehose destination has its own data delivery frequency. For more information, see [Configure buffering hints](create-configure-backup.md#buffering-hints "create-configure-backup.md#buffering-hints").

**Duplicate records**

Amazon Data Firehose uses at-least-once semantics for data delivery. In some circumstances, such
as when data delivery times out, delivery retries by Amazon Data Firehose might introduce duplicates if
the original data-delivery request eventually goes through. This applies to all destination
types that Amazon Data Firehose supports, except for Amazon S3 destinations, Apache Iceberg
Tables, and Snowflake destinations.

# Configuring

EKS Runtime Monitoring for multiple-account environments (API)

In a multiple-account environments, only the delegated GuardDuty administrator account can enable or disable EKS Runtime Monitoring
for the member accounts, and manage GuardDuty agent management for the EKS clusters belonging to the
member accounts in their organization. The GuardDuty member accounts can't modify this
configuration from their accounts. The delegated GuardDuty administrator account account manages their member accounts
using AWS Organizations. For more information about multi-account environments, see [Managing
multiple accounts](guardduty_accounts.md "guardduty_accounts.md").

This section provides steps to configure EKS Runtime Monitoring and manage the GuardDuty
security agent for the EKS clusters that belong to the delegated GuardDuty administrator account.

Based on the [Approaches to manage GuardDuty
security agent in Amazon EKS clusters](how-runtime-monitoring-works-eks.md#eksrunmon-approach-to-monitor-eks-clusters "how-runtime-monitoring-works-eks.md#eksrunmon-approach-to-monitor-eks-clusters"), you can choose

If there<br>were any problems changing the detector settings for an<br>account, that account ID is listed along with a summary of<br>the issue.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Monitor all EKS clusters but exclude some of them<br>(using exclusion tag) | 1. Add a tag to the EKS cluster that you want to<br>exclude from being monitored. The key-value pair is<br>`GuardDutyManaged`-`false`.<br>For more information about adding the tag, see<br>[Working with tags using the CLI, API, or<br>eksctl](../../../eks/latest/userguide/eks-using-tags.md#tag-resources-api-sdk "../../../eks/latest/userguide/eks-using-tags.md#tag-resources-api-sdk") in the<br>**Amazon EKS User Guide**.<br>2. To prevent modification of tags, except by the trusted entities, use the policy provided in<br>[Prevent tags from being modified except by authorized principals](../../../organizations/latest/userguide/orgs_manage_policies_scps_examples_tagging.md#example-require-restrict-tag-mods-to-admin "../../../organizations/latest/userguide/orgs_manage_policies_scps_examples_tagging.md#example-require-restrict-tag-mods-to-admin") in the<br>_AWS Organizations User Guide_. In this policy, replace the following details:<br>• Replace `ec2:CreateTags` with `eks:TagResource`.<br>• Replace `ec2:DeleteTags` with `eks:UntagResource`.<br>• Replace `access-project` with `GuardDutyManaged`<br>• Replace `123456789012` with the AWS account ID of the<br>trusted entity.<br>When you have more than one trusted entities, use the following example to add<br>multiple `PrincipalArn`:<br>`<br>"aws:PrincipalArn":["arn:aws:iam::123456789012:role/org-admins/iam-admin", "arn:aws:iam::123456789012:role/org-admins/iam-admin", "arn:aws:iam::123456789012:role/org-admins/iam-admin"]<br>`<br>3. NoteAlways add the exclusion tag to your EKS<br>cluster before setting the `STATUS` of<br>`EKS_RUNTIME_MONITORING` to<br>`ENABLED`; otherwise, the GuardDuty<br>security agent will be deployed on all the EKS<br>clusters in your account.<br>To selectively enable EKS Runtime Monitoring for your member<br>accounts, run the [updateMemberDetectors](../APIReference/API_UpdateMemberDetectors.md "../APIReference/API_UpdateMemberDetectors.md") API<br>operation using your own `detector<br>ID`.<br>Set the status for<br>`EKS_ADDON_MANAGEMENT` as<br>`ENABLED`.<br>GuardDuty will manage the deployment of and updates to<br>the security agent for all the Amazon EKS clusters that<br>have not been excluded from being monitored.<br>Alternatively, you can use the AWS CLI command by<br>using your own regional detector ID.<br>To find the `detectorId` for your account and current Region, see the<br>\*_Settings_<br>• page in the [https://console.aws.amazon.com/guardduty/](https://console.aws.amazon.com/guardduty/ "https://console.aws.amazon.com/guardduty/") console,<br>or run the [ListDetectors](../APIReference/API_ListDetectors.md "../APIReference/API_ListDetectors.md") API.<br>The following example enables both<br>`EKS_RUNTIME_MONITORING` and<br>`EKS_ADDON_MANAGEMENT`:<br>``<br>aws guardduty update-member-detectors --detector-id `12abc34d567e8fa901bc2d34e56789f0` --account-ids `111122223333` --features '[{"Name" : "EKS_RUNTIME_MONITORING", "Status" : "`ENABLED`", "AdditionalConfiguration" : [{"Name" : "EKS_ADDON_MANAGEMENT", "Status" : "`ENABLED`"}] }]'<br>``<br>NoteYou can also pass a list of account IDs<br>separated by a space.<br>When the code has successfully executed, it<br>returns an empty list of<br>`UnprocessedAccounts`. If there were<br>any problems changing the detector settings for an<br>account, that account ID is listed along with a<br>summary of the issue. |

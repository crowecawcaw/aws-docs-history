# Setting trace flags in RDS for Microsoft SQL Server

A SQL Server trace flag is a setting you can turn on or off to change how the database
engine behaves. You can use trace flags to enable hidden features, fix performance
problems, or override default server behavior. In effect, each trace flag acts as an
on/off switch that changes the default behavior of SQL Server.

For a complete list of trace flags available in Microsoft SQL Server, see [DBCC TRACEON - Trace Flags](https://learn.microsoft.com/en-us/sql/t-sql/database-console-commands/dbcc-traceon-trace-flags-transact-sql?view=sql-server-ver17#trace-flags "https://learn.microsoft.com/en-us/sql/t-sql/database-console-commands/dbcc-traceon-trace-flags-transact-sql?view=sql-server-ver17#trace-flags") in the Microsoft documentation.

As a managed service, RDS for SQL Server restricts global server-level settings. You
can configure only specific trace flags as startup parameters through RDS for SQL Server
[DB parameter groups](parameter-groups-overview.md "parameter-groups-overview.md"). The following table lists the supported trace flags in
RDS for SQL Server.

###### Important

We strongly recommend that you test and validate thoroughly before you
enable trace flags in production. Trace flags are useful for performance tuning and
troubleshooting, but incorrect usage can cause instability, suboptimal query plans, or
resource issues.

| 692        | Disables fast inserts while bulk loading data into heap or<br>clustered indexes (supported on SQL Server 2016 and later).                                                                                                                                                                                                                                                                                                                                                                                         |

| 1211       | Disables lock escalation based on memory pressure or number of<br>locks. SQL Server will not escalate row or page locks to table<br>locks.                                                                                                                                                                                                                                                                                                                                                                        |
| 1222       | Returns deadlock information in XML format (enhanced version of<br>1204).                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 1224       | Disables lock escalation based on the number of locks (memory<br>pressure can still activate lock escalation).                                                                                                                                                                                                                                                                                                                                                                                                    |

| 8285       | Fixes an assertion error (`IndexRowScanner.cpp:<br>m_versionStatus.IsVisible()`) in databases with change data<br>capture (CDC) or Read Committed Snapshot Isolation (RCSI) enabled. | 8780       | Gives the optimizer more time to find a better plan.                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

Used<br>alongside trace flag 11042 to prevent access violation dumps when<br>sessions are reset for reuse.                                                                                                                                                                                                                                                                                  |
| 9481       | Forces the query optimizer to use the legacy cardinality<br>estimation model (SQL Server 2012 and earlier), regardless of the<br>database compatibility level. Alternatives: at the database level, use<br>`ALTER DATABASE SCOPED CONFIGURATION`; at the query<br>level, use the `QUERYTRACEON` query hint.                                                                                                                                                                                                       |
| 9492       | Disables parallelism for `SELECT INTO` (bulk insert)<br>operations at the instance level to reduce `LATCH_EX` waits<br>on `METADATA_SEQUENCE_GENERATOR`. Might slightly reduce<br>performance but improves overall stability.                                                                                                                                                                                                                                                                                     |
| 9592       | Enables log stream compression for synchronous availability<br>groups. Log stream compression is disabled by default on synchronous<br>availability groups because compression adds latency. Enabling it can<br>reduce network bandwidth usage between replicas at the cost of<br>additional CPU and some added latency. Applies to: SQL Server 2016<br>(13.0) and later.                                                                                                                                         |
| 11024      | In SQL Server 2017, auto-update of incremental statistics on<br>partitioned tables can be delayed. This happens because the root<br>node's modification count resets to zero if no single partition<br>exceeds its local threshold, even when the combined count exceeds the<br>root threshold. Trace flag 11024 fixes this by keeping the root node's<br>modification count as the true sum of all partition modifications,<br>ensuring timely statistics updates. Applies to: SQL Server 2017 CU3 and<br>later. |
| 11042      | SQL Server 2019 CU14 fixed wrong results in parallel plans using<br>`SESSION_CONTEXT`. However, this fix can cause access<br>violation dumps when sessions are reset for reuse. Workaround: enable<br>both trace flags together: trace flag 11042 (disables parallelism for<br>`SESSION_CONTEXT`) and trace flag 9432 (disables the original<br>CU14 fix). | 12502      | Fixes high `PREEMPTIVE_OS_QUERYREGISTRY` waits by<br>disabling external authorization policies for on-premises SQL Server<br>instances. Applies to: SQL Server 2022 CU5+.                                                                                                                                                                                                                                                                                                                                         |
| 12618      | Allows the Automatic Plan Correction (APC) feature to perform<br>multiple consecutive regression checks on the same plan, enabling it to<br>gather more statistics before deciding on a correction. | 12656      | Adds a 5-minute delay before Automatic Plan Correction (APC) runs<br>its regression check after detecting a plan change. This avoids skewed<br>results from fast-running queries and accounts for longer-running or<br>timeout-prone queries affected by the change. Applies to: SQL Server<br>2022 CU4+.                                                                                                                                                                                                         |

###### Note

From SQL Server 2016 Service Pack 1 (SP1) and later, we recommend that you use the
`USE HINT` query hint at the query level instead of trace flags 4138 and 4139. Always test thoroughly before you apply this change in production.

###### Important

Unflushed Query Store data might be lost during shutdown when you use trace flag 7745.
For an immediate SQL Server shutdown, use `SHUTDOWN WITH NOWAIT` instead of
this trace flag.

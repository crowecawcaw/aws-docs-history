

# Revisions
<a name="revisions"></a>

Check the [CHANGELOG.md](https://github.com/aws-solutions-library-samples/guidance-for-connected-mobility-on-aws/blob/main/CHANGELOG.md) file in the GitHub repository for a detailed record of all software changes.


| Version | Date | Description | 
| --- | --- | --- | 
| 1.5.1 | September 2026 | Rewrote the **Monitor the Guidance** chapter and included it in the guide for the first time. The chapter had never been wired into `book.adoc`, so it had never rendered into the published guide, and had remained a short note about Service Catalog AppRegistry while the Guidance grew 44 Amazon CloudWatch alarms. It now documents the full alarm inventory by stack with the metric and threshold behind each family, the deployment step required to route alarms to a person (most publish to Amazon SNS topics with no subscription until you add one), how an alarm can go quiet while continuing to report OK, the log group for every component, and the metrics worth a dashboard that no alarm covers. AppRegistry is retained as a section. Added a **Data products** section to the platform guide covering the lifecycle an operator drives — declaring a product, mapping a producer’s vocabulary onto the platform’s canonical signals and events, and delivery — including why connection type and authentication are separate axes, why credentials are held by reference, why severity is mapped rather than inferred from a producer’s own labels, the four-step onboarding path, the criteria under which a source earns its own Flink application, and the current limitations of the definition layer. Replaced the **Disaster recovery and resiliency** chapter, which had been unfilled template text and had never rendered, with a short chapter grounded in the deployed configuration: what each component tolerates on Availability Zone loss, a caution that two Kafka brokers at replication factor 2 leave no redundancy after a single broker loss, the redeploy-and-restore path for a Region event, the two things that do not recover (in-flight telemetry and cached live vehicle state), and the three changes that carry most of the benefit if stricter recovery targets are required. Deleted five further orphaned template chapters that had never rendered and whose premise — that this Guidance is a managed AWS service with its own IAM action prefix — does not hold. | 
| 1.5.0 | September 2026 | Refreshed the guide for the v0.4.0 release. Retired the Virtual Fleet Operator (VFO) Bedrock multi-agent stack and its Fleet Command Center UI; the in-UI conversational assistant now consumes the companion Agentic Vehicle Experience (AVX) accelerator’s Amazon Bedrock AgentCore text runtime and is wired via `runtimeConfig.json`. Adopted single-environment (staging) posture across the deploy, plan, and uninstall chapters. Added a new **Third-party data delivery** chapter — a reusable Kafka-on-AWS delivery pattern grounded in the new Connected Services subscription plane. Added a **Client surfaces** section to the platform guide comparing the three client applications — Fleet Manager console, Connected Services portal, and driver companion app — by audience, authority, scope of visibility, and the APIs each consumes. Promoted the Connected Services portal from a subsection of the Fleet Manager console walkthrough to its own section, covering its seven screen domains, its `subscriber` and `connected-services` authorization groups, and the distinction between its live API-backed surfaces and its fixture-backed illustrative ones. Added a **Driver companion app** section documenting the native iOS surface, its screens, the CMS and AVX APIs it consumes directly, its single-vehicle driver scope, and its build-time endpoint configuration. Added Fleet Intelligence surfaces (ADP-backed cross-region Athena analytics). Updated the simulator image pin to `v0.4.0` (`cms-sim-service:v0.4.0` now carries vehicle-side SOVD handlers). Introduced the Remote diagnostics chapter — remote vehicle diagnostics aligned to the ASAM SOVD data model over MQTT on AWS IoT Core, with on-demand DTC read and clear, freeze frames, safety-classified diagnostic routines with typed results, and diagnostic sessions handed off to a dealer. Added guidance for migrating from AWS IoT FleetWise. Refreshed Fleet Manager console screenshots for the regrouped navigation, and removed the Dashboard and Analytics sections, which described views the console no longer provides. | 
| 1.4.0 | July 2026 | Refreshed the guide for the current release: three-mode telemetry with OEM cloud connectors, in-UI conversational fleet operations via Amazon Bedrock agents, expanded Region posture, updated phase-based deployment process, and a telemetry-versus-other-component cost breakdown. Diagrams will be refreshed in a follow-on update. |



# Version 2.28.1 and 3.28.1
<a name="rn-2-28-1"></a>

This release includes AWS Elemental Live and AWS Elemental Statmux version 2.28.1, and AWS Elemental Conductor Live version 3.28.1.

## New features in version 2.28.1
<a name="rn-2-28-1-new-features"></a>

This release includes the following new features:

Security updates  
This release includes updates that address potential security issues.

## Resolved issues in Elemental Live 2.28.1
<a name="rn-2-28-1-resolved-live"></a>

The following table lists the issues that are resolved in Elemental Live 2.28.1.


| Key | Topic | Description | 
| --- | --- | --- | 
| V2308875836 | Audio, Nielsen | Previously, when you enabled Nielsen watermarking, audio could drift ahead of video after each input switch. This issue has been fixed for switches between inputs that have the same audio sample rate and channel count. | 
| P470092114 | Audio | Previously, an event that ran for about 926 days without an input switch could start dropping audio. This issue has been fixed. | 
| V2400818686 | API, Audio | Previously, when you updated an event with the REST API, its audio selector groups could be duplicated instead of updated. This issue has been fixed. | 
| V2323293642 | Captions, DVB Teletext | Previously, after an input switch, when several DVB Teletext caption selectors shared a packet identifier (PID), only the first language had captions. This issue has been fixed. | 
| P484730223 | Captions | Previously, when you prepared an input, switched away from it, and then switched back to it, its captions could be missing from the outputs. This issue has been fixed. | 
| P510217468 | Captions | Previously, when outputs used several channels of an input's embedded captions, such as CC1 and CC3, one channel could lose captions after an input switch. This issue was introduced in version 2.28.0 and has been fixed. | 
| P519940624 | Captions | Previously, when Elemental Live cleared CEA-608 captions, such as at an input switch, captions on CC2, CC3, and CC4 could stay on screen. This issue has been fixed. | 
| P482222778 | Captions, DVB-Sub | Previously, when you used one embedded caption selector for both DVB-Sub captions and embedded passthrough captions, the embedded captions were lost. This issue has been fixed. | 
| TDP-210 | Captions | Previously, some captions on CC3 or CC4 could appear for only one frame. This issue has been fixed. | 
| V2344207117 | Captions, SCTE-35 | Previously, embedded 608 captions could stop in the output after the first SCTE-35 ad avail. This issue has been fixed. | 
| P510327877 | Event processing, Timecode | Previously, when Elemental Live generated timecode for an input with an invalid frame rate, all events on the node could fail. This issue has been fixed. | 
| EML-10912 | Inputs, Input failover | Previously, an event that used a hot backup input could fail during input failover. This issue has been fixed. | 
| V2307138347 | Inputs, Event processing | Previously, when you prepared an input after a scheduled input switch to the input that was already active, the event could fail. This issue has been fixed. | 
| D476660020 | Inputs, HLS | Previously, audio could stop on HLS inputs with a separate audio rendition until you restarted the event. This issue has been fixed. | 
| P511000342 | Inputs, HLS | Previously, when you added an HLS input with audio rendition selectors to the input list, a simultaneous input switch could cause black frames. This issue has been fixed. | 
| V2314086343 | Inputs | Previously, memory usage grew each time a file input with Loop Source enabled looped. This issue has been fixed. | 
| P441178615 | Inputs, RTP | Previously, RTP inputs with very high packet rates, such as JPEG XS, could report false packet loss. This issue has been fixed. | 
| P528948357 | Inputs, SRT | Previously, an SRT input that repeatedly failed to connect could degrade encoder performance over time. This issue has been fixed. | 
| P537871981 | Inputs, TS | Previously, some transport stream inputs that carried DVB Teletext could be detected as AV1 video, and the input could fail. This issue has been fixed. | 
| TDP-199 | Inputs, TS | Previously, transport stream inputs could report false continuity counter errors, which could trigger an unnecessary input failover. This issue has been fixed. | 
| P485630114 | Outputs, MP4, HEVC | Previously, MP4-based outputs with 10-bit or 4:2:2 HEVC video signaled the video as 8-bit 4:2:0. This issue has been fixed. | 
| V2403314242 | Outputs, CMAF Ingest, SCTE-35 | Previously, in CMAF Ingest outputs, a SCTE-35 time signal End marker with the same event ID as its Start marker was delayed. This issue has been fixed. | 
| P491107487 | Outputs, Amazon S3 | Previously, HLS, DASH ISO, and MS Smooth outputs to Amazon S3 or S3-compatible destinations ignored the FileCache Size setting. During a destination outage, they could drop segments early. This issue has been fixed. | 
| P470383493 | Outputs, HLS | Previously, HLS audio-only outputs with packed audio segments used a video content type, which some players reject. This issue has been fixed. | 
| V2372495977 | Outputs, HLS, Captions | Previously, in HLS output groups, caption-only outputs used the event start time for the $dt$, $d$, and $t$ identifiers in every segment file name. These identifiers now update for each segment, which changes the caption segment file names. | 
| D484864506 | Outputs, MP4 | Previously, MP4-based outputs other than DASH ISO, such as HLS fMP4, could have incorrect HE-AAC audio timing when the video had no B-frames. This issue has been fixed. | 
| P441493597 | Outputs, SRT | Previously, Elemental Live ignored the latency that you configured on an SRT output and used the default of 120 ms. This issue has been fixed. | 
| V2238976565 | Outputs, TS | Previously, after you paused a constant bitrate (CBR) UDP/TS output for a long time and then unpaused it, the output could stop sending data. This issue was introduced in version 2.28.0 and has been fixed. | 
| V2372063207 | Platform | Previously, a log file was never rotated and could grow to several GB. This issue has been fixed. | 
| P495863865 | Scheduling | Previously, when you created a schedule 12 to 24 hours before its first start time, the scheduled events could be created late. This issue has been fixed. | 
| P432012220 | SCTE-35, HLS | Previously, when a SCTE-35 Program End and Program Start arrived together, HLS outputs could mark the next Program End with the wrong event ID. This issue has been fixed. | 
| P474021370 | SCTE-35 | Previously, a SCTE-35 segmentation cue-in with a different event ID could end the active avail early. This issue has been fixed. A segmentation cue-in now ends an avail only when the event IDs match. | 
| V2285676609 | SCTE-35 | Previously, SCTE-35 passthrough could stop for an input after it reached the end of its input clipping and the event later switched back to it. This issue has been fixed. | 
| TDP-80 | SCTE-35 | Previously, when the duration of an active ad avail changed, some outputs could miss the change, so ad signaling could differ between outputs. This issue has been fixed. | 
| P455331278 | SCTE-35 | Previously, SCTE-35 splice out messages with no duration and no matching splice in could cause dropped audio in long-running events. This issue has been fixed. | 
| P429140724 | SCTE-35, ESAM | Previously, with output locking, SCTE-35 messages conditioned by Event Signaling and Management (ESAM) could have an incorrect splice time on the follower node. This issue has been fixed. |

## Resolved issues in Conductor Live 3.28.1
<a name="rn-2-28-1-resolved-cl3"></a>

The following table lists the issues that are resolved in Conductor Live 3.28.1.


| Key | Topic | Description | 
| --- | --- | --- | 
| D482775726 | Platform, High availability | Previously, the Conductor Live high availability health check could report false faults, which caused repeated failovers. This issue has been fixed. | 
| V2281605698 | Platform, High availability | Previously, after a Conductor Live high availability failover, the new primary Conductor could lose its mount points and delete the mount points on worker nodes. This issue has been fixed. | 
| EDS-18264 | Platform | Previously, Conductor Live kept all cleared alerts from worker nodes, which could slow the database and node removal on long-running clusters. Conductor Live now removes these alerts after they have been cleared for 30 days. | 
| P496323727 | User Interface | Previously, the Conductor Live profile editor hid the Prefer SMPTE 2038 checkbox for saved SMPTE 2022-7 inputs. This issue has been fixed. |

# Working with time

signals

Time signals inserted by the REST API can be one of the “ad avail” types, or some
other type, depending on what you specify in the segmentation descriptor in the
request.

###### Effect of creating a time signal

Insertion of a time signal modifies the data stream as it is being encoded.

The effect of time signals on other parts of the content
depends on how the event is set up, as described in earlier
chapters of this guide. So it depends on the Ad Avail mode,
whether manifest decoration is enabled, blanking and blackout are
enabled, and whether passthrough is enabled.

## Insert a new

time signal message

Inserts a SCTE-35 message of type time_signal in the stream either immediately or
at a specified time. The command always includes a start time (in the time tag) and a
duration (included in the segmentation descriptor).

**HTTP URL**

```
POST <IP address of Live node>/live_events/<ID of event>/time_signal
```

**Body of HTTP**

The XML body contains one **time_signal** element
containing the following tags:

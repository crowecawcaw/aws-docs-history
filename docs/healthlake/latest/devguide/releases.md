

# AWS HealthLake releases
<a name="releases"></a>

The following table shows when features and updates were released for AWS HealthLake. For more information about a release, see the linked topic.

| Change | Description | Date | 
| --- |--- |--- |
| [Updated AWS managed policy: AmazonHealthLakeReadOnlyAccess](#releases) | The `AmazonHealthLakeReadOnlyAccess` managed policy now includes read-only permissions for HealthLake Data Transformation Agent. With this policy, you can view transformation profiles and profile versions, view transformation job status, and validate source C-CDA files. You can't create or modify these resources. For more information, see [AWS managed policies for AWS HealthLake](https://docs.aws.amazon.com/healthlake/latest/devguide/security-iam-awsmanpol.html). | August 4, 2026 | 
| [`$translate` operation for ConceptMap](#releases) | AWS HealthLake now supports the FHIR [`$translate`](https://hl7.org/fhir/r4/conceptmap-operation-translate.html) operation for ConceptMap resources on R4 data stores, allowing you to map codes between clinical terminologies (for example, SNOMED CT to ICD-10-CM) using ConceptMaps ingested into your data store. Invoke by using GET or POST at type-level (`/ConceptMap/$translate`) or instance-level (`/ConceptMap/{id}/$translate`), with filtering by canonical URL, source/target value set, and target code system. For more information, see [the $translate operation for ConceptMap resources](https://docs.aws.amazon.com/healthlake/latest/devguide/reference-fhir-operations-translate.html). | July 29, 2026 | 
| [Resource matching (gated preview)](#releases) | AWS HealthLake now supports resource matching for seven FHIR resource types. When enabled, it continuously evaluates resources using healthcare identifiers and creates FHIR Linkage resources for matches without modifying the original resources. Request access to resource matching during preview by [completing this form](https://pulse.amazon/survey/0B005AOL?p=0). For more information, see [Matching duplicate FHIR resources](https://docs.aws.amazon.com/healthlake/latest/devguide/resource-matching.html). | July 23, 2026 | 
| [HealthLake Data Transformation Agent (preview)](#releases) | HealthLake Data Transformation Agent is a fully managed capability that converts C-CDA and CSV healthcare data into FHIR R4 resources. Its healthcare-aware AI agent helps create and refine reusable, versioned transformation profiles. It supports real-time and bulk conversion, with output written to Amazon S3 or directly into a HealthLake data store. For more information, see [Transforming healthcare data](https://docs.aws.amazon.com/healthlake/latest/devguide/data-transformation.html). | July 23, 2026 | 
| [Security and tag filtering for $export and $davinci-data-export](#releases) | The `$export` and `$davinci-data-export` operations now support `_security` and `_tag` query parameters for filtering exported resources by `meta.security` and `meta.tag` Coding values. This enables multi-tenant export and granular access control using the standard FHIR `system\|code` format. | April 30, 2026 | 
| [$bulk-member-match operation](#releases) | AWS HealthLake now supports the `$bulk-member-match` operation for processing multiple member match requests asynchronously. This operation enables healthcare organizations to efficiently match hundreds of members' unique identifiers across different healthcare systems using demographic and coverage information in a single bulk request.+ Handles up to 500 members per request with up to 5 concurrent operations per data store<br />+ Results categorized into MatchedMembers, NonMatchedMembers, and ConsentConstrainedMembers groups<br />+ Integrates with `$davinci-data-export` for end-to-end bulk data workflows<br />For more information, see [`$bulk-member-match` operation for HealthLake](reference-fhir-operations-bulk-member-match.md). | April 1, 2026 | 
| [Asynchronous bundle transactions](#releases) | AWS HealthLake now supports asynchronous `Bundle` type `transaction`, allowing you to submit transactions with up to 500 resources. HealthLake queues the transaction for processing and immediately returns a polling URL to check status and retrieve results. For more information, see [Asynchronous bundle transactions](https://docs.aws.amazon.com/healthlake/latest/devguide/managing-fhir-resources-bundle.html#managing-fhir-resources-async-transactions). | March 24, 2026 | 
| [Patch Support in Bundle Operations](#releases) | HealthLake now supports [Bundle Patch](https://docs.aws.amazon.com/healthlake/latest/devguide/managing-fhir-resources-patch.html#patch-supported-formats), enabling both FHIRPath and JSON Patch for Transaction and Batch bundles, as well as FHIRPath for the Patch API. This capability allows customers to patch resources directly within Bundle operations without requiring full resource replacement, reducing payload sizes, simplifying integration workflows, and enabling faster data ingestion. | March 20, 2026 |



# Example queries for HealthLake data

Clinical informatics teams, population health analysts, and data engineers use these queries as starting points for registries, cohorts, quality reporting, and care gap analysis.

The queries use synthetic data generated by Synthea and Amazon Athena (Trino) syntax. To learn about creating a data store preloaded with Synthea data, see [Creating a HealthLake data store](managing-data-stores-create.md). To run the queries in another engine, see [Adapting the examples for other engines](#integrating-analytics-example-queries-translate).

**Important**  
The examples use synthetic data. With real data, the results contain protected health information (PHI). Select only the columns that you need, and govern query results according to your organization's policies.

## How organizations use HealthLake analytics
<a name="integrating-analytics-example-queries-uses"></a>

Teams across healthcare use HealthLake analytics to answer recurring clinical and population health questions:
+ **Patient registries** – A current list of patients with demographics, used for outreach, panel management, and data quality review.
+ **Cohorts and care gaps** – Patients who meet clinical criteria, such as a diagnosis and an age range, and whether they received recommended care.
+ **Quality reporting** – Measure denominators, numerators, and exclusions built from conditions, observations, and procedures.
+ **Health equity** – Address and demographic fields support analysis by geography and population group.
+ **Medication safety** – Active prescriptions and documented medications support reconciliation and polypharmacy review.

The examples on this page are illustrative. They aren't certified implementations of any quality measure.

## Before you run the examples
<a name="integrating-analytics-example-queries-before"></a>

Keep the following points in mind before you run the examples.

Count current resources only  
Tables keep every version of each resource, and the examples don't filter versions, so counts and cohorts can be inflated. Before you rely on a result, apply the current-version pattern in [Resource versions](integrating-analytics.md#integrating-analytics-tables-versions) to each table.

Join resources by reference  
FHIR resources refer to a patient with `subject.reference`, in the form `Patient/{{id}}`. The examples join on `CONCAT('Patient/', patient.id) = {{table}}.subject.reference`.

Filter on codes, not display text  
Display text varies by source system and capitalization. Filter on `code.coding[1].code` and its code system instead: SNOMED CT (`http://snomed.info/sct`) and ICD-10-CM (`http://hl7.org/fhir/sid/icd-10-cm`) for conditions, LOINC (`http://loinc.org`) for observations, and RxNorm (`http://www.nlm.nih.gov/research/umls/rxnorm`) for medications. Codings are arrays, so the code you need might not be first.

Results in the console  
In the Athena console, you can sort the results of any query or download them.

## Working with nested elements
<a name="integrating-analytics-example-queries-nested"></a>

The following tabs show how to read common nested elements. Each tab uses the patterns in the clinical examples.

------
#### [ Patient: extension ]

You use the `extension` element to create custom fields in a data store.

This example accesses the `extension` element in the `Patient` resource type.

When you import your HealthLake data store into Athena, Athena parses the elements of a resource type differently. Because the structure of the `element` is variable, the schema can't fully specify it. To handle that variability, the elements inside the array appear as strings.

In the table description of `Patient`, the `extension` element appears as `array<string>`. This means you can access the array elements by using an index value. To access the elements of the string, you must use `json_extract`.

Here is a single entry from the `extension` element found in the patient table.

```JSON
[{
		"valueString": "Kerry175 Cummerata161",
		"url": "http://hl7.org/fhir/StructureDefinition/patient-mothersMaidenName"
	},
	{
		"valueAddress": {
			"country": "DE",
			"city": "Hamburg",
			"state": "Hamburg"
		},
		"url": "http://hl7.org/fhir/StructureDefinition/patient-birthPlace"
	},
	{
		"valueDecimal": 0.0,
		"url": "http://synthetichealth.github.io/synthea/disability-adjusted-life-years"
	},
	{
		"valueDecimal": 5.0,
		"url": "http://synthetichealth.github.io/synthea/quality-adjusted-life-years"
	}
]
```

Even though this is valid JSON, Athena treats it as a string.

This query returns the `patient-mothersMaidenName` and `patient-birthPlace` extensions as columns. To access these elements, use different array indices and `json_extract`.

```SQL
SELECT
    extension[1],
    json_extract(extension[1], '$.valueString') AS MothersMaidenName,
    extension[2],
    json_extract(extension[2], '$.valueAddress.city') AS birthPlace
FROM patient
```

#### [ Patient: age ]

Age is *not* an element of the Patient resource type in FHIR. The following two examples filter based on age.

Because age isn't an element, use `birthDate` for the SQL queries. To see how Athena ingests an element, search for the table name under **Tables and views**. You can see that it's of type **string**.

**Example 1**: Calculating a value for age

This sample SQL query uses the built-in SQL functions `current_date` and `year` to extract those components. It then subtracts them to return a patient's age as a column called `age`.

```SQL
SELECT
	(year(current_date) - year(date(birthdate))) as age
FROM patient
```

**Example 2**: Filtering for patients who are born before `2019-01-01` and are `male`.

This SQL query shows how to use the `CAST` function to cast the `birthDate` element as type `DATE`. It also shows how to filter on two criteria in the `WHERE` clause. Because Athena ingests the element as type **string** by default, you must `CAST` it as type `DATE`. Then you can use the `<` operator to compare it to a different date, `2019-01-01`. To add a second criterion to the `WHERE` clause, use `AND`.

```SQL
SELECT birthdate
FROM patient
-- birthdate is a string, so cast it to DATE before comparing.
WHERE CAST(birthdate AS DATE) < CAST('2019-01-01' AS DATE) AND gender = 'male'
```

------
#### [ Location ]

This example finds locations in the Location resource type where the city is Attleboro.

```SQL
SELECT *
FROM Location
WHERE address.city='ATTLEBORO'
LIMIT 10;
```

#### [ Observation: coded values ]

The `Observation` resource type stores measurements and simple assertions about a patient, device, or other subject.

This query finds observations with SNOMED CT code 266919005 (Never smoked tobacco). Smoking status is a common preventive care data element.

The commented-out WHERE clause would exclude NLP-generated resources; see [Filtering NLP-generated resources](#integrating-analytics-example-queries-nlp).

```SQL
SELECT valueCodeableConcept.coding[1].code
FROM Observation
WHERE  valueCodeableConcept.coding[1].code = '266919005'
-- WHERE meta.tag[1] is NULL
```

Athena imports this column as a [`struct`](https://iceberg.apache.org/spec/#schemas-and-data-types). You can access elements inside it by using dot notation.

## Clinical and population health examples
<a name="integrating-analytics-example-queries-list"></a>

Each example lists the use case, what the query returns, and how to adapt it.

**Patient population**

**Example Find patients by demographics**  
**Use case:** Build a patient registry for outreach, panel management, and health equity analysis by geography.  
**Returns:** Each patient with name, age, gender, marital status, address, coordinates, and deceased status.  

```SQL
SELECT
    id
    , CONCAT(name[1].family, ' ', name[1].given[1]) as name
    , (year(current_date) - year(date(birthdate))) as age
    , gender as gender
    , json_extract(extension[1], '$.valueString') as MothersMaidenName
    , json_extract(extension[2], '$.valueAddress.city') as birthPlace
    , maritalstatus.coding[1].display as maritalstatus
    , address[1].line[1] as addressline
    , address[1].city as city
    , address[1].district as district
    , address[1].state as state
    , address[1].postalcode as postalcode
    , address[1].country as country
    , json_extract(address[1].extension[1], '$.extension[0].valueDecimal') as latitude
    , json_extract(address[1].extension[1], '$.extension[1].valueDecimal') as longitude
    , telecom[1].value as telNumber
    , deceasedboolean as deceasedIndicator
    , deceaseddatetime
FROM {{resource-link-name}}.patient;
```
Replace {{resource-link-name}} with the name of your resource link.  
**Adapt it:** Filter on `deceasedboolean` to exclude deceased patients from outreach lists.

**Example Find a diabetes cohort**  
**Use case:** Build a diabetes cohort of patients aged 18 to 75 who are due for glycemic testing, aligned with measures such as CMS122.  
**Returns:** Each condition and observation for patients aged 18 to 75 who have diabetes.  

```SQL
SELECT patient.id as patientId,
	condition.id as conditionId,
	CONCAT(name [ 1 ].family, ' ', name [ 1 ].given [ 1 ]) as name,
	(year(current_date) - year(date(birthdate))) AS age,
	CASE
		WHEN condition.encounter.reference IS NOT NULL THEN condition.encounter.reference
		WHEN observation.encounter.reference IS NOT NULL THEN observation.encounter.reference
	END as encounterId,
	CASE
		WHEN condition.encounter.type IS NOT NULL THEN condition.encounter.type
		WHEN observation.encounter.type IS NOT NULL THEN observation.encounter.type
	END AS encountertype,
	condition.code.coding [ 1 ].code as diagnosisCode,
	condition.code.coding [ 1 ].display as diagnosisDescription,
	observation.category [ 1 ].coding [ 1 ].code as categoryCode,
	observation.category [ 1 ].coding [ 1 ].display as categoryDescription,
	observation.code.coding [ 1 ].code as observationCode,
	observation.code.coding [ 1 ].display as observationDescription,
	effectivedatetime AS observationDateTime,
	CASE
      WHEN valuequantity.value IS NOT NULL THEN CONCAT(CAST(valuequantity.value AS VARCHAR),' ',valuequantity.unit)
      WHEN valueCodeableConcept.coding [ 1 ].code IS NOT NULL THEN CAST(valueCodeableConcept.coding [ 1 ].code AS VARCHAR)
      WHEN valuestring IS NOT NULL THEN CAST(valuestring AS VARCHAR)
      WHEN valueboolean IS NOT NULL THEN CAST(valueboolean AS VARCHAR)
      WHEN valueinteger IS NOT NULL THEN CAST(valueinteger AS VARCHAR)
      WHEN valueratio IS NOT NULL THEN CONCAT(CAST(valueratio.numerator.value AS VARCHAR),'/',CAST(valueratio.denominator.value AS VARCHAR))
      WHEN valuerange IS NOT NULL THEN CONCAT(CAST(valuerange.low.value AS VARCHAR),'-',CAST(valuerange.high.value AS VARCHAR))
      WHEN valueSampledData IS NOT NULL THEN CAST(valueSampledData.data AS VARCHAR)
      WHEN valueTime IS NOT NULL THEN CAST(valueTime AS VARCHAR)
      WHEN valueDateTime IS NOT NULL THEN CAST(valueDateTime AS VARCHAR)
      WHEN valuePeriod IS NOT NULL THEN valuePeriod.start
      WHEN component[1] IS NOT NULL THEN CONCAT(CAST(component[2].valuequantity.value AS VARCHAR),' ',CAST(component[2].valuequantity.unit AS VARCHAR), '/', CAST(component[1].valuequantity.value AS VARCHAR),' ',CAST(component[1].valuequantity.unit AS VARCHAR))
    END AS observationvalue,
	CASE
		WHEN condition.meta.tag [ 1 ].display = 'SYSTEM_GENERATED' THEN 'YES'
		WHEN condition.meta.tag [ 1 ].display IS NULL THEN 'NO'
		WHEN observation.meta.tag [ 1 ].display = 'SYSTEM_GENERATED' THEN 'YES'
		WHEN observation.meta.tag [ 1 ].display IS NULL THEN 'NO'
  	END AS IsSystemGenerated,
  CAST(
    json_extract(
      condition.modifierextension [ 1 ],
      '$.valueDecimal'
    ) AS int
  ) AS confidenceScore
FROM {{resource-link-name}}.patient,
	{{resource-link-name}}.condition,
	{{resource-link-name}}.observation
WHERE CONCAT('Patient/', patient.id) = condition.subject.reference
	AND CONCAT('Patient/', patient.id) = observation.subject.reference
  	AND (year(current_date) - year(date(birthdate))) >= 18
  	AND (year(current_date) - year(date(birthdate))) <= 75
  	AND condition.code.coding [ 1 ].display like ('%diabetes%');
```
Replace {{resource-link-name}} with the name of your resource link.  
This query returns one row for each condition and observation pair, so a patient can appear many times. Aggregate by patient for counts.
**Adapt it:** Replace the display-text filter with a code filter, for example SNOMED CT 44054006 (Diabetes mellitus type 2), and limit observations to HbA1c results (LOINC 4548-4).

**Clinical history**

**Example Find each patient's problem list**  
**Use case:** Review a patient's problem list, profile comorbidities, and support risk adjustment.  
**Returns:** Each condition with code, category, onset, severity, clinical status, and verification status.  

```SQL
SELECT
	patient.id as patientId
    , condition.id  as conditionId
    , CONCAT(name[1].family, ' ', name[1].given[1]) as name
    , condition.meta.tag[1].display
    , json_extract(condition.modifierextension[1], '$.valueDecimal') AS confidenceScore
    , category[1].coding[1].code as categoryCode
    , category[1].coding[1].display as categoryDescription
    , code.coding[1].code as diagnosisCode
    , code.coding[1].display as diagnosisDescription
    , onsetdatetime
    , severity.coding[1].code as severityCode
    , severity.coding[1].display as severityDescription
    , verificationstatus.coding[1].display as verificationStatus
    , clinicalstatus.coding[1].display as clinicalStatus
    , encounter.reference as encounterId
    , encounter.type as encountertype
FROM {{resource-link-name}}.patient, {{resource-link-name}}.condition
WHERE CONCAT('Patient/', patient.id) = condition.subject.reference
ORDER BY name;
```
Replace {{resource-link-name}} with the name of your resource link.  
**Adapt it:** Filter on `clinicalstatus` to keep only active conditions.

    , code.coding[1].code as observationCode
    , code.coding[1].display as observationDescription
    , effectivedatetime
    , CASE
		WHEN valuequantity.value IS NOT NULL THEN CONCAT(CAST(valuequantity.value AS VARCHAR),' ',valuequantity.unit)
      	WHEN valueCodeableConcept.coding [ 1 ].code IS NOT NULL THEN CAST(valueCodeableConcept.coding [ 1 ].code AS VARCHAR)
      	WHEN valuestring IS NOT NULL THEN CAST(valuestring AS VARCHAR)
      	WHEN valueboolean IS NOT NULL THEN CAST(valueboolean AS VARCHAR)
      	WHEN valueinteger IS NOT NULL THEN CAST(valueinteger AS VARCHAR)
      	WHEN valueratio IS NOT NULL THEN CONCAT(CAST(valueratio.numerator.value AS VARCHAR),'/',CAST(valueratio.denominator.value AS VARCHAR))
      	WHEN valuerange IS NOT NULL THEN CONCAT(CAST(valuerange.low.value AS VARCHAR),'-',CAST(valuerange.high.value AS VARCHAR))
      	WHEN valueSampledData IS NOT NULL THEN CAST(valueSampledData.data AS VARCHAR)
      	WHEN valueTime IS NOT NULL THEN CAST(valueTime AS VARCHAR)
      	WHEN valueDateTime IS NOT NULL THEN CAST(valueDateTime AS VARCHAR)

    END AS observationvalue

## Adapting the examples for other engines
<a name="integrating-analytics-example-queries-translate"></a>

The examples use the following Athena syntax:
+ Arrays use 1-based indexes and dot notation, for example `name[1].family`.
+ Structs use dot notation with no index, for example `maritalstatus.text`.
+ `extension` entries are JSON strings, so use `json_extract` to read them.
+ Date elements such as `birthDate` are strings, so `CAST` them to `DATE` to compare.

Other engines differ in four places. Adjust the examples as shown in the following table.


**SQL differences across engines**  

| Engine | Table name | Array index | JSON strings | 
| --- | --- | --- | --- | 
| [Amazon Athena](integrating-athena.md) | patient, in the resource link database | 1-based, name[1] | json\_extract | 
| [Amazon Redshift Spectrum](integrating-redshift-spectrum.md) | healthlake.patient (the external schema) | 0-based, name[0], in the SELECT list only | JSON\_EXTRACT\_PATH\_TEXT on a VARCHAR cast | 
| [Apache Spark on Amazon EMR](integrating-spark.md) | healthlake.`{{target-database-name}}`.patient | 0-based, name[0] | get\_json\_object | 
| [Databricks](integrating-databricks.md) | {{catalog-name}}.{{schema-name}}.patient | 0-based, name[0] | get\_json\_object or the : operator | 
| [Snowflake](integrating-snowflake.md) | The Iceberg table that you created for each HealthLake table | 0-based, name[0] | PARSE\_JSON | 

Also keep the following engine-specific limitations in mind:
+ When you adapt a query for Snowflake, a join works only if you created an Iceberg table for every table in the query.
+ Redshift Spectrum doesn't allow array elements in a `WHERE` clause, and the examples filter on elements such as `meta.tag[1]`. Rewrite those filters as described in [SQL differences in Redshift Spectrum](integrating-redshift-spectrum.md#integrating-redshift-spectrum-sql).

## Filtering NLP-generated resources
<a name="integrating-analytics-example-queries-nlp"></a>

If you used HealthLake integrated natural language processing (NLP), the resources that it generated have the `SYSTEM_GENERATED` tag in `meta.tag`. For more information, see [Integrated natural language processing (NLP) for HealthLake](integrating-nlp.md).

------
#### [ Condition ]

The `Condition` resource type stores diagnosis data about issues that have risen to a level of concern.

This query returns `Condition` resources and excludes the `SYSTEM_GENERATED` resources.

```SQL
SELECT *
FROM condition
WHERE meta.tag[1] is NULL
```

The `modifierextension` element identifies the `DocumentReference` that generated a set of conditions. Use `json_extract` to read the nested JSON, and `CAST` it so you can compare with `LIKE`.

```SQL
SELECT
    meta.tag[1].display as SystemGenerated,
    json_extract(modifierextension[4], '$.valueReference.reference') as DocumentReference
FROM condition
WHERE meta.tag[1].display = 'SYSTEM_GENERATED'

AND CAST(json_extract(modifierextension[4], '$.valueReference.reference') as VARCHAR) LIKE '%DocumentReference/{{document-reference-id}}%'
```

Replace {{document-reference-id}} with the ID of the DocumentReference resource.

------
#### [ MedicationStatement ]

The `MedicationStatement` resource type stores details about medications that a patient has taken, is taking, or will take.

This query filters on a single patient by identifier and on the `SYSTEM_GENERATED` tag.

```SQL
SELECT *
FROM medicationstatement
WHERE meta.tag[1].display = 'SYSTEM_GENERATED' AND subject.reference = 'Patient/{{patient-id}}';
```

Replace {{patient-id}} with the ID of the patient.

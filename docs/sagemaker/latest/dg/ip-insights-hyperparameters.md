# IP Insights Hyperparameters

In the [`CreateTransformJob`](../APIReference/API_CreateTransformJob.md "../APIReference/API_CreateTransformJob.md")
request, you specify the training algorithm. You can also specify algorithm-specific
hyperparameters as string-to-string maps. The following table lists the hyperparameters
for the Amazon SageMaker AI IP Insights algorithm.

| Parameter Name                    | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `num_entity_vectors`              | The number of entity vector representations (entity embedding<br>vectors) to train. Each entity in the training set is randomly<br>assigned to one of these vectors using a hash function. Because of<br>hash collisions, it might be possible to have multiple entities<br>assigned to the same vector. This would cause the same vector to<br>represent multiple entities. This generally has a negligible effect<br>on model performance, as long as the collision rate is not too<br>severe. To keep the collision rate low, set this value as high as<br>possible. However, the model size, and, therefore, the memory<br>requirement, for both training and inference, scales linearly with<br>this hyperparameter. We recommend that you set this value to twice<br>the number of unique entity identifiers.<br>**Required**<br>Valid values: 1 ≤ positive integer ≤ 250,000,000 |
| `vector_dim`                      | The size of embedding vectors to represent entities and IP<br>addresses. The larger the value, the more information that can be<br>encoded using these representations. In practice, model size scales<br>linearly with this parameter and limits how large the dimension can<br>be. In addition, using vector representations that are too large can<br>cause the model to overfit, especially for small training datasets.<br>Overfitting occurs when a model doesn't learn any pattern in the<br>data but effectively memorizes the training data and, therefore,<br>cannot generalize well and performs poorly during inference. The<br>recommended value is 128.<br>**Required**<br>Valid values: 4 ≤ positive integer ≤ 4096                                                                                                                                                      |
| `batch_metrics_publish_interval`  | The interval (every X batches) at<br>which<br>the Apache MXNet Speedometer function prints the<br>training speed of the network (samples/second).<br>**Optional**<br>Valid values: positive integer ≥ 1<br>Default value: 1,000                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `epochs`                          | The number of passes over the training data. The optimal value<br>depends on your data size and learning rate. Typical values range<br>from 5 to 100.<br>**Optional**<br>Valid values: positive integer ≥ 1<br>Default value: 10                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `learning_rate`                   | The learning rate for the optimizer. IP Insights use a<br>gradient-descent-based Adam optimizer. The learning rate effectively<br>controls the step size to update model parameters at each iteration.<br>Too large a learning rate can cause the model to diverge because the<br>training is likely to overshoot a minima. On the other hand, too<br>small a learning rate slows down convergence. Typical values range<br>from 1e-4 to 1e-1.<br>**Optional**<br>Valid values: 1e-6 ≤ float ≤ 10.0<br>Default value: 0.001                                                                                                                                                                                                                                                                                                                                                             |
| `mini_batch_size`                 | The number of examples in each mini batch. The training<br>procedure processes data in mini batches. The optimal value depends<br>on the number of unique account identifiers in the dataset. In<br>general, the larger the `mini_batch_size`, the faster the<br>training and the greater the number of possible<br>shuffled-negative-sample combinations. However, with a large<br>`mini_batch_size`, the training is more likely to<br>converge to a poor local minimum and perform relatively worse for<br>inference.<br>**Optional**<br>Valid values: 1 ≤ positive integer ≤ 500000<br>Default value: 10,000                                                                                                                                                                                                                                                                        |
| `num_ip_encoder_layers`           | The number of fully connected layers used to encode the IP<br>address embedding. The larger the number of layers, the greater the<br>model's capacity to capture patterns among IP addresses. However,<br>using a large number of layers increases the chance of<br>overfitting.<br>**Optional**<br>Valid values: 0 ≤ positive integer ≤ 100<br>Default value: 1                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `random_negative_sampling_rate`   | The number of random negative samples,<br>R,<br>to generate per input example. The training procedure relies on<br>negative samples to prevent the vector representations of the model<br>collapsing to a single point. Random negative sampling generates R<br>random IP addresses for each input account in the mini batch. The<br>sum of the `random_negative_sampling_rate` (R) and<br>`shuffled_negative_sampling_rate` (S) must be in the<br>interval: 1 ≤ R + S ≤ 500.<br>**Optional**<br>Valid values: 0 ≤ positive integer ≤ 500<br>Default value: 1                                                                                                                                                                                                                                                                                                                           |
| `shuffled_negative_sampling_rate` | The number of shuffled negative samples,<br>S,<br>to generate per input example. In some cases, it helps to use more<br>realistic negative samples that are randomly picked from the<br>training data itself. This kind of negative sampling is achieved by<br>shuffling the data within a mini batch. Shuffled negative sampling<br>generates S negative IP addresses by shuffling the IP address and<br>account pairings within a mini batch. The sum of the<br>`random_negative_sampling_rate` (R) and<br>`shuffled_negative_sampling_rate` (S) must be in the<br>interval: 1 ≤ R + S ≤ 500.<br>**Optional**<br>Valid values: 0 ≤ positive integer ≤ 500<br>Default value: 1                                                                                                                                                                                                         |
| `weight_decay`                    | The weight decay coefficient. This parameter adds an L2<br>regularization factor that is required to prevent the model from<br>overfitting the training data.<br>**Optional**<br>Valid values: 0.0 ≤ float ≤ 10.0<br>Default value: 0.00001                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
